## 1. 操作系统特点与功能
### 问：什么是操作系统？
答：操作系统是计算机系统中最基本的系统软件，它位于硬件和应用程序之间，负责管理计算机硬件资源，并为用户和应用程序提供方便、安全、高效的运行环境。
**背诵版**：操作系统是管理硬件资源、控制程序运行、为用户和应用程序提供服务的系统软件。

### 问：操作系统的主要功能有哪些？
答：操作系统主要有五大功能：处理机管理、存储器管理、文件管理、设备管理和用户接口管理。
处理机管理负责 CPU 分配和进程调度。
存储器管理负责内存分配、回收、地址转换、虚拟内存。
文件管理负责文件和目录的创建、删除、读写、保护。
设备管理负责管理 I/O 设备，比如磁盘、键盘、打印机。
用户接口负责提供命令行、图形界面和系统调用。
**背诵版**：操作系统五大功能：处理机管理、存储器管理、文件管理、设备管理、用户接口。

### 问：操作系统的基本特征是什么？
答：操作系统的基本特征是并发、共享、虚拟和异步。
并发是多个程序宏观上同时运行，微观上交替执行。
共享是多个进程共同使用系统资源。
虚拟是把一个物理资源抽象成多个逻辑资源，比如虚拟内存。
异步是进程执行速度和顺序不确定，受调度和资源影响。
**背诵版**：操作系统四大特征：并发、共享、虚拟、异步。并发是基础，共享是目的，虚拟是手段，异步是结果。

## 2. 中断 vs 系统调用
### 问：什么是中断？
答：中断是 CPU 在执行程序时，因为外部事件、异常事件或软件请求，暂停当前程序，转去执行中断处理程序，处理完后再回到原程序继续执行的机制。
例如键盘输入、鼠标点击、磁盘读写完成、定时器到时、除零错误，都可能触发中断。
**背诵版**：中断是 CPU 暂停当前程序，转去处理突发事件，处理完再返回的机制。

### 问：中断有什么作用？
答：中断让 CPU 不必一直等待慢速设备，提高了系统效率。它也是操作系统实现多任务、I/O 管理、异常处理和系统调用的重要基础。
**背诵版**：中断让 CPU 能及时响应外部事件，是多任务和 I/O 管理的基础。

### 问：什么是系统调用？
答：系统调用是用户程序请求操作系统内核提供服务的一种接口。用户程序不能直接访问硬件和内核资源，所以必须通过系统调用进入内核态，由操作系统完成操作。
例如：open()打开文件、read()读文件、write()写文件、fork()创建进程、exec()执行新程序。
**背诵版**：系统调用是用户程序请求操作系统内核服务的接口。

### 问：中断和系统调用有什么区别？
答：中断通常是由外部设备、异常或定时器触发的，具有被动性和突发性；系统调用是用户程序主动请求操作系统服务。
**背诵版**：中断是事件打断 CPU；系统调用是程序主动请求内核服务。

### 问：系统调用为什么要从用户态切换到内核态？
答：因为用户程序不能直接执行特权指令，也不能直接访问硬件资源。系统调用涉及文件、进程、设备、内存等敏感操作，所以必须切换到内核态，由操作系统完成。
**背诵版**：用户态不能直接操作硬件和内核资源，所以系统调用必须进入内核态。

## 3. 进程 vs 线程、通信方式、资源共享
### 问：什么是进程？
答：进程是程序的一次执行过程，是系统进行资源分配和调度的基本单位。一个进程拥有独立的地址空间、代码段、数据段、堆、栈、打开文件等资源。
**背诵版**：进程是程序的一次执行，是资源分配的基本单位。

### 问：什么是线程？
答：线程是进程中的一个执行流，是 CPU 调度的基本单位。一个进程可以包含多个线程。同一进程内的线程共享进程资源，比如地址空间、全局变量、打开文件，但每个线程有自己的栈和寄存器上下文。
**背诵版**：线程是进程内的执行流，是 CPU 调度的基本单位。

### 问：进程和线程有什么区别？
答：进程是资源分配的基本单位，线程是 CPU 调度的基本单位。
进程有独立地址空间，线程共享同一进程的地址空间。
进程切换开销大，线程切换开销小。
进程之间通信复杂，线程之间通信方便。
一个进程崩溃一般不会直接影响其他进程；一个线程崩溃可能导致整个进程崩溃。
**背诵版**：进程拥有资源，线程负责执行。进程隔离性强、开销大；线程共享资源、开销小，但安全性更差。

### 问：进程间通信方式有哪些？
答：常见进程间通信方式有管道、消息队列、共享内存、信号量、信号、套接字。
管道适合有亲缘关系的进程传输字节流。
消息队列适合进程之间传递结构化消息。
共享内存速度最快，因为多个进程直接访问同一块内存，但需要配合同步机制。
信号量主要用于进程同步和互斥。
信号用于通知进程某个事件发生。
套接字可以用于不同主机之间的网络通信。
**背诵版**：进程间通信：管道、消息队列、共享内存、信号量、信号、套接字。共享内存最快，但要配合同步互斥。

### 问：线程之间如何通信？
答：同一进程内的线程共享地址空间，所以线程之间可以通过全局变量、共享数据结构进行通信。但因为共享数据容易产生竞争，所以需要互斥锁、信号量、条件变量等机制保证同步。
**背诵版**：线程共享进程地址空间，通信方便，但必须注意同步互斥。

## 4. 进程状态与调度策略
### 问：进程有哪些基本状态？
答：进程通常有三种基本状态：就绪态、运行态、阻塞态。
就绪态表示进程已经具备运行条件，只等 CPU。
运行态表示进程正在 CPU 上执行。
阻塞态表示进程因为等待某个事件暂时不能运行，比如等待 I/O 完成。
**背诵版**：就绪态：等 CPU。运行态：正在执行。阻塞态：等事件或 I/O。

### 问：进程状态之间如何转换？
答：就绪态获得 CPU 后变为运行态。
运行态时间片用完或被抢占后变为就绪态。
运行态等待 I/O 或资源时变为阻塞态。
阻塞态等待的事件完成后变为就绪态。
**背诵版**：就绪 --调度--> 运行；运行 --时间片完/被抢占--> 就绪；运行 --等待 I/O--> 阻塞；阻塞 --事件完成--> 就绪。

### 问：什么是调度？
答：调度是操作系统从就绪队列中选择一个进程或线程，把 CPU 分配给它运行的过程。
**背诵版**：调度就是从就绪队列中选择一个进程使用 CPU。

### 问：调度算法评价指标有哪些？
答：常见指标有 CPU 利用率、系统吞吐量、周转时间、等待时间、响应时间和公平性。
CPU 利用率越高越好。
吞吐量表示单位时间完成的进程数量，越大越好。
周转时间是从进程提交到完成的总时间，越短越好。
等待时间是进程在就绪队列中等待 CPU 的总时间，越短越好。
响应时间是从提交请求到第一次得到响应的时间，交互式系统尤其重视。
**背诵版**：调度评价指标：CPU 利用率、吞吐量、周转时间、等待时间、响应时间、公平性。

## 5. 读写者问题实现方式、文件组织结构
### 问：什么是读者-写者问题？
答：读者-写者问题是经典同步问题，描述多个进程或线程共享同一份数据时，读操作可以并发进行，但写操作必须互斥。
规则：读读可以同时；读写不能同时；写写不能同时。
**背诵版**：读者-写者问题的核心是：允许多个读者同时读，但写者必须独占资源。

### 问：读者优先怎么实现？
答：读者优先是指只要当前有读者在读，后续读者可以继续进入，写者必须等待。通常用 readcount 记录当前读者数量，第一个读者加写锁，最后一个读者释放写锁。
核心逻辑：第一个读者进入：锁住写者。中间读者进入：只增加读者数量。最后一个读者离开：释放写锁。缺点是写者可能长期等待，出现写者饥饿。
**背诵版**：读者优先允许读者连续进入，优点是读效率高，缺点是写者可能饥饿。

### 问：写者优先怎么实现？
答：写者优先是指一旦有写者等待，后续读者不能再插队，必须让写者先写。这样可以避免写者长期等待。
**背诵版**：写者优先防止写者饥饿，但可能降低读者并发性。

### 问：公平读写怎么实现？
答：公平读写通常按请求到达顺序排队，读者和写者都不能无限插队，可以用队列、信号量或条件变量实现。
**背诵版**：公平读写按照到达顺序处理，避免读者或写者饥饿。

### 问：文件组织结构有哪些？
答：文件组织结构可以从“文件内部记录怎么存”和“文件在磁盘上怎么分配”两个角度理解。
文件内部组织常见有顺序文件、索引文件、索引顺序文件。
磁盘空间分配常见有连续分配、链接分配、索引分配。
顺序文件适合顺序访问。索引文件适合随机访问。
连续分配访问快，但容易产生外部碎片。链接分配不需要连续空间，但随机访问慢。索引分配通过索引块记录所有数据块地址，随机访问方便。
**背诵版**：文件组织：顺序、索引、索引顺序。磁盘分配：连续分配、链接分配、索引分配。

## 6. 死锁：定义、四个条件、预防方法
### 问：什么是死锁？
答：死锁是指多个进程在运行过程中，因为互相等待对方占有的资源而无法继续执行的状态。
举例：进程 A 占有资源 1，等待资源 2；进程 B 占有资源 2，等待资源 1；A 等 B，B 等 A，两个都无法继续。
**背诵版**：死锁是多个进程互相等待对方资源，导致都无法继续执行。

### 问：死锁产生的四个必要条件是什么？
答：死锁产生的四个必要条件是互斥条件、请求并保持条件、不可剥夺条件、循环等待条件。
互斥条件：资源一次只能被一个进程使用。
请求并保持条件：进程已经占有资源，同时又请求新的资源。
不可剥夺条件：进程占有的资源不能被强行夺走，只能主动释放。
循环等待条件：多个进程形成环形等待链。
**背诵版**：死锁四条件：互斥、请求并保持、不可剥夺、循环等待。

### 问：如何预防死锁？
答：预防死锁就是破坏死锁产生的四个必要条件之一。
破坏互斥条件：让资源可以共享。但很多资源天然不能共享，所以不常用。
破坏请求并保持条件：要求进程一次性申请所有资源，拿不到就一个都不占有。
破坏不可剥夺条件：当进程请求不到新资源时，释放已经占有的资源。
破坏循环等待条件：给资源编号，规定进程必须按固定顺序申请资源。
**背诵版**：死锁预防就是破坏四条件：破坏请求并保持：一次申请所有资源；破坏不可剥夺：申请失败就释放已有资源；破坏循环等待：按资源编号顺序申请。

### 问：死锁处理方法有哪些？
答：死锁处理方法有四类：预防死锁、避免死锁、检测死锁、解除死锁。
预防死锁是在设计上破坏死锁条件。
避免死锁是在资源分配前判断是否安全，比如银行家算法。
检测死锁是允许死锁发生，然后通过算法检测。
解除死锁是发现死锁后，撤销进程或剥夺资源。
**背诵版**：死锁处理：预防、避免、检测、解除。

## 7. 哲学家进餐问题实现方式
### 问：什么是哲学家进餐问题？
答：哲学家进餐问题是经典的进程同步问题。几个哲学家围坐在桌子旁，每两个人之间有一只筷子。每个哲学家吃饭需要同时拿到左右两只筷子。如果所有哲学家都先拿左筷子，再等待右筷子，就会发生死锁。
**背诵版**：哲学家进餐问题说明多个进程竞争多个资源时，可能因为循环等待产生死锁。

### 问：哲学家进餐问题为什么会死锁？
答：如果每个哲学家都拿起左边的筷子，然后等待右边的筷子，那么每个人都占有一个资源，又等待别人释放另一个资源，形成循环等待，所以发生死锁。
**背诵版**：每个哲学家都占有一只筷子并等待另一只筷子，形成循环等待，因此死锁。

### 问：如何解决哲学家进餐问题？
答：常见方法有四种。
第一，限制最多只允许 n-1 个哲学家同时拿筷子，这样至少有一个哲学家能拿到两只筷子吃饭。
第二，要求哲学家必须同时拿到左右两只筷子，否则一只也不拿。
第三，给筷子编号，规定所有哲学家必须按编号顺序拿筷子，从而破坏循环等待。
第四，让奇数号哲学家先拿左筷子，偶数号哲学家先拿右筷子，避免所有人同方向等待。
**背诵版**：哲学家进餐问题的解决思路：限制人数；同时拿两只筷子；资源编号按序申请；奇偶哲学家拿筷子顺序不同。

## 8. 银行家算法
### 问：银行家算法是什么？
答：银行家算法是一种死锁避免算法。它在给进程分配资源之前，先判断分配后系统是否仍处于安全状态。如果安全，就分配；如果不安全，就暂时不分配。
**背诵版**：银行家算法用于死锁避免，核心是分配前先判断系统是否安全。

### 问：什么是安全状态？
答：安全状态是指系统存在一个安全序列，使所有进程都能按照某种顺序依次获得所需资源并顺利完成。
如果存在安全序列，系统就是安全状态。如果不存在安全序列，系统就是不安全状态。
注意：不安全状态不一定已经死锁，但有可能发展成死锁。
**背诵版**：安全状态是存在一个进程完成顺序，使所有进程最终都能完成。不安全状态不一定死锁，但可能导致死锁。

### 问：银行家算法中的几个矩阵是什么？
答：Available 表示当前系统可用资源数量。
Max 表示每个进程最多需要多少资源。
Allocation 表示每个进程已经分配到多少资源。
Need 表示每个进程还需要多少资源。
关系：Need = Max - Allocation
**背诵版**：Available：当前可用。Max：最大需求。Allocation：已经分配。Need：还需要。Need = Max - Allocation。

### 问：银行家算法怎么判断是否安全？
答：先设置 Work = Available。
然后找一个尚未完成的进程 Pi，使得：Need[i] <= Work。
如果找得到，说明 Pi 可以完成。Pi 完成后释放资源：Work = Work + Allocation[i]。继续找下一个进程。
如果最后所有进程都能完成，则系统安全；如果找不到可以完成的进程，则系统不安全。
**背诵版**：银行家算法步骤：Work = Available；找 Need <= Work 的进程；找到就假设它完成并释放资源；能让所有进程完成就是安全，否则不安全。

## 9. 进程调度算法：FCFS、SJF、SRTF、优先级、RR、多级反馈队列
### 问：FCFS 先来先服务是什么？
答：FCFS 按照进程到达的先后顺序调度，谁先到谁先运行，属于非抢占式调度。
优点是简单公平。缺点是短作业可能等待很久，容易出现“护航效应”：一个长作业占着 CPU，后面一堆短作业都等着。
**背诵版**：FCFS：先到先服务，简单公平，但短作业可能等待很久。

### 问：SJF 短作业优先是什么？
答：SJF 优先调度运行时间最短的作业，通常是非抢占式。
优点是平均等待时间和平均周转时间较短。缺点是必须预知作业运行时间，而且长作业可能饥饿。
**背诵版**：SJF：短作业优先，平均等待时间短，但长作业可能饥饿。

### 问：SRTF 最短剩余时间优先是什么？
答：SRTF 是抢占式的短作业优先。每当有新进程到达时，系统比较当前运行进程的剩余时间和新进程的运行时间，谁剩余时间更短就运行谁。
**背诵版**：SRTF：抢占式 SJF，谁剩余时间最短谁运行。

### 问：优先级调度是什么？
答：优先级调度是根据进程优先级选择进程运行，优先级高的先运行。它可以是抢占式，也可以是非抢占式。
缺点是低优先级进程可能长期得不到运行，发生饥饿。解决方法是老化机制，即等待时间越长，优先级逐渐提高。
**背诵版**：优先级调度：优先级高者先运行。缺点是低优先级可能饥饿，可用老化机制解决。

### 问：RR 时间片轮转是什么？
答：RR 把 CPU 时间划分为固定长度的时间片。每个进程轮流运行一个时间片，如果时间片用完还没执行完，就回到就绪队列末尾等待下一轮。
适合分时系统和交互式系统。时间片太大会退化成 FCFS；时间片太小会导致频繁切换，开销大。
**背诵版**：RR：每个进程轮流运行一个时间片，适合交互式系统。时间片太大像 FCFS，太小切换开销大。

### 问：多级反馈队列是什么？
答：多级反馈队列把就绪队列分成多个优先级队列。高优先级队列时间片短，低优先级队列时间片长。新进程先进入高优先级队列，如果在一个时间片内没运行完，就降到低一级队列。
它兼顾短作业、交互式进程和长作业。
**背诵版**：多级反馈队列：新进程先高优先级，运行不完就逐级下降。它兼顾响应时间和公平性，是较综合的调度算法。

### 问：这些调度算法怎么对比？
答：FCFS 最简单，但可能让短作业等太久。
SJF 平均等待时间短，但长作业可能饥饿。
SRTF 是抢占式 SJF，响应更及时，但调度开销更大。
优先级调度适合区分任务重要性，但低优先级可能饥饿。
RR 适合交互系统，公平性好。
多级反馈队列综合性最强，兼顾短作业、交互响应和长作业。
**背诵版**：FCFS 简单；SJF 平均等待短；SRTF 是抢占式短作业优先；优先级适合重要任务；RR 适合分时交互；多级反馈队列最综合。

## 10. 分页 vs 分段
### 问：什么是分页？
答：分页是把进程的逻辑地址空间划分为大小相等的页，把物理内存划分为大小相等的页框。程序运行时，页可以离散地装入不同页框中。分页通过页表完成逻辑地址到物理地址的转换。
**背诵版**：分页把逻辑空间分成固定大小的页，把内存分成固定大小的页框。

### 问：什么是分段？
答：分段是按照程序的逻辑结构把地址空间划分为多个段，比如代码段、数据段、堆段、栈段。每个段长度可以不同。分段更符合程序员的逻辑视角。
**背诵版**：分段按程序逻辑划分地址空间，如代码段、数据段、栈段。

### 问：分页和分段有什么区别？
答：分页的单位大小固定，由系统决定；分段的单位大小不固定，由程序逻辑决定。
分页对用户不可见，主要为了提高内存利用率；分段对用户可见，主要为了符合程序逻辑和方便保护共享。
分页会产生内部碎片；分段会产生外部碎片。
分页地址由页号和页内偏移组成；分段地址由段号和段内偏移组成。
**背诵版**：分页：固定大小，系统管理，可能有内部碎片。分段：逻辑划分，大小不定，可能有外部碎片。

### 问：分页为什么没有外部碎片？
答：因为分页把内存划分为大小相等的页框，任何页都可以放入任意空闲页框，不要求连续空间，所以不会产生外部碎片。但最后一页可能装不满，所以会产生内部碎片。
**背诵版**：分页不要求连续空间，所以没有外部碎片；页内可能用不满，所以有内部碎片。

## 11. 虚拟内存、共享内存
### 问：什么是虚拟内存？
答：虚拟内存是操作系统提供的一种内存管理技术。它让程序认为自己拥有一个连续、很大的地址空间，但实际上只有部分页面在物理内存中，其他部分可以暂时放在磁盘上。
**背诵版**：虚拟内存让程序看到一个大的连续地址空间，而实际数据可分散在内存和磁盘中。

### 问：虚拟内存有什么作用？
答：虚拟内存扩大了程序可用的地址空间，使程序可以比物理内存更大；它也提高了内存利用率，因为只把当前需要的页面装入内存；同时还提供了进程隔离和内存保护。
**背诵版**：虚拟内存的作用：扩大地址空间，提高内存利用率，实现进程隔离和保护。

### 问：虚拟内存怎么实现？
答：虚拟内存通常通过分页机制、页表、地址转换、缺页中断、页面置换算法实现。
程序访问某个虚拟地址时，MMU 根据页表把虚拟地址转换为物理地址。如果发现页面不在内存中，就触发缺页中断，操作系统把页面从磁盘调入内存。如果内存满了，还要通过页面置换算法淘汰某个页面。
**背诵版**：虚拟内存依靠分页、页表、缺页中断和页面置换实现。

### 问：什么是缺页中断？
答：缺页中断是指程序访问的页面不在物理内存中，CPU 触发中断，让操作系统把所需页面从磁盘调入内存。
**背诵版**：缺页中断就是访问的页不在内存，需要操作系统从磁盘调入。

### 问：什么是共享内存？
答：共享内存是进程间通信的一种方式。多个进程把同一块物理内存映射到自己的地址空间中，从而可以直接读写这块内存。
它是最快的进程间通信方式，因为数据不需要在内核和用户空间之间反复拷贝。
但共享内存需要配合信号量、互斥锁等同步机制，否则容易出现数据竞争。
**背诵版**：共享内存是多个进程映射同一块内存进行通信，速度最快，但需要同步互斥。

## 12. 页面置换算法
### 问：什么是页面置换？
答：页面置换是指发生缺页中断时，如果物理内存已经满了，操作系统需要选择一个页面淘汰出去，再把新页面调入内存。
**背诵版**：页面置换就是内存满时，选择一个页换出去，给新页腾位置。

### 问：OPT 最佳置换算法是什么？
答：OPT 淘汰未来最长时间不会被访问的页面。它的缺页率最低，但需要知道未来访问序列，所以实际系统无法真正实现，通常作为理论最优标准。
**背诵版**：OPT：淘汰未来最久不用的页，理论最优，实际不可实现。

### 问：FIFO 先进先出算法是什么？
答：FIFO 淘汰最早进入内存的页面。它实现简单，但可能淘汰经常使用的页面，并且可能出现 Belady 异常。
Belady 异常是指给进程分配更多页框后，缺页次数反而增加。
**背诵版**：FIFO：谁先进内存谁先被淘汰，简单但可能出现 Belady 异常。

### 问：LRU 最近最久未使用算法是什么？
答：LRU 淘汰最近最长时间没有被访问的页面。它利用局部性原理，认为最近很久没用的页面，将来也可能暂时不用。
**背诵版**：LRU：淘汰最近最久没用的页，利用局部性原理。

### 问：Clock 时钟算法是什么？
答：Clock 算法是 LRU 的近似实现。它给每个页面设置访问位，页面按环形队列排列。
查找淘汰页时，如果访问位为 1，就把它改为 0，并跳过；如果访问位为 0，就淘汰该页面。
**背诵版**：Clock：访问位为 1 就给第二次机会，改 0 后跳过；访问位为 0 就淘汰。

### 问：页面置换算法怎么对比？
答：OPT 理论最优但不能实现。
FIFO 简单但效果不稳定，可能出现 Belady 异常。
LRU 效果较好，但实现开销较大。
Clock 是 LRU 的近似算法，开销较小，实际系统常用。
**背诵版**：OPT 最优不可实现；FIFO 简单但可能异常；LRU 效果好但开销大；Clock 近似 LRU，实用性强。

## 13. 缓冲区溢出处理 & 生产者消费者问题
### 问：什么是缓冲区溢出？
答：缓冲区溢出是指程序向一块固定大小的缓冲区写入超过其容量的数据，导致多余数据覆盖相邻内存区域，可能破坏程序数据，甚至被攻击者利用执行恶意代码。
例如 C 语言中使用不安全的 strcpy、gets 等函数，就可能导致缓冲区溢出。
**背诵版**：缓冲区溢出是写入数据超过缓冲区大小，导致覆盖相邻内存的错误。

### 问：缓冲区溢出有什么危害？
答：它可能导致程序崩溃、数据被破坏、控制流被劫持，严重时攻击者可以执行恶意代码。
**背诵版**：缓冲区溢出可能导致崩溃、数据破坏和代码执行漏洞。

### 问：如何防止缓冲区溢出？
答：第一，进行边界检查，写入前检查数据长度。
第二，使用安全函数，比如 fgets、strncpy、snprintf，避免 gets、strcpy、sprintf 这类不安全函数。
第三，使用栈保护机制，如 Stack Canary。
第四，使用地址空间随机化 ASLR，让攻击者难以预测地址。
第五，使用不可执行栈 NX/DEP，防止栈上代码被执行。
第六，尽量使用带边界检查的高级语言或安全库。
**背诵版**：防止缓冲区溢出：边界检查、安全函数、栈保护、ASLR、NX/DEP。

### 问：如果是生产者-消费者中的缓冲区满了怎么办？
答：如果缓冲区满了，生产者不能继续放入数据，必须阻塞等待；如果缓冲区空了，消费者不能继续取数据，也必须阻塞等待。
通常用三个信号量实现：empty：空缓冲区数量；full：满缓冲区数量；mutex：互斥访问缓冲区。
生产者：P(empty) → P(mutex) → 放入数据 → V(mutex) → V(full)
消费者：P(full) → P(mutex) → 取出数据 → V(mutex) → V(empty)
**背诵版**：缓冲区满，生产者等 empty；缓冲区空，消费者等 full；访问缓冲区要用 mutex 互斥。

## 14. 磁盘调度算法与空间管理
### 问：为什么需要磁盘调度？
答：磁盘访问速度远慢于 CPU 和内存。磁盘读写需要移动磁头，寻道时间是主要开销之一。磁盘调度算法通过优化磁头移动顺序，减少寻道距离，提高磁盘访问效率。
**背诵版**：磁盘调度的目标是减少磁头移动距离，提高磁盘 I/O 效率。

### 问：FCFS 磁盘调度是什么？
答：FCFS 按照请求到达顺序依次访问磁道。优点是公平简单。缺点是磁头可能来回大幅移动，效率低。
**背诵版**：FCFS：按请求顺序访问，公平但磁头移动可能很大。

### 问：SSTF 最短寻道时间优先是什么？
答：SSTF 每次选择距离当前磁头位置最近的请求。优点是平均寻道距离较短。缺点是远处请求可能长期得不到服务，产生饥饿。
**背诵版**：SSTF：每次选最近磁道，效率较高，但可能饥饿。

### 问：SCAN 电梯算法是什么？
答：SCAN 让磁头像电梯一样沿一个方向移动，沿途处理请求，到达一端后再反向移动。优点是比较公平，避免磁头频繁来回跳动。
**背诵版**：SCAN：磁头像电梯一样单方向服务，到端点再反向。

### 问：C-SCAN 循环扫描是什么？
答：C-SCAN 只在一个方向上服务请求，到达一端后直接回到另一端，再继续同方向服务。它比 SCAN 更公平，因为所有请求等待时间更均匀。
**背诵版**：C-SCAN：只按一个方向服务，到端点后跳回起点继续。

### 问：LOOK 和 C-LOOK 是什么？
答：LOOK 是 SCAN 的改进版，磁头不一定移动到磁盘最边缘，只移动到当前方向上最远的请求位置就返回。
C-LOOK 是 C-SCAN 的改进版，只移动到最远请求位置，然后跳到另一端的最远请求位置继续。
**背诵版**：LOOK 不走到磁盘尽头，只走到最远请求。C-LOOK 是循环版 LOOK。

### 问：磁盘空间管理方法有哪些？
答：常见方法有空闲表法、空闲链表法、位示图法和成组链接法。
空闲表法记录每段连续空闲区的起始位置和长度。
空闲链表法把空闲块链接起来。
位示图法用每一位表示一个磁盘块是否空闲。
成组链接法常用于 Unix，把空闲块分组管理，提高效率。
**背诵版**：磁盘空闲空间管理：空闲表、空闲链表、位示图、成组链接。

## 15. 文件系统组织结构
### 问：文件系统是什么？
答：文件系统是操作系统中负责管理文件和目录的模块。它把磁盘上的数据组织成文件和目录，并提供创建、删除、读写、查找、权限控制等功能。
**背诵版**：文件系统负责在磁盘上组织、管理和访问文件。

### 问：文件系统通常由哪些部分组成？
答：文件系统通常包括文件、目录、文件控制块、空闲空间管理、磁盘块分配、权限管理等。
文件控制块 FCB 记录文件的元信息，比如文件名、大小、位置、权限、创建时间等。
Unix/Linux 中常用 inode 保存文件元数据，目录项主要保存文件名和 inode 编号。
**背诵版**：文件系统包括文件、目录、FCB/inode、磁盘块分配和空闲空间管理。

### 问：目录结构有哪些？
答：常见目录结构有单级目录、二级目录、树形目录、无环图目录和通用图目录。
单级目录结构简单，但文件名容易冲突。
二级目录给每个用户一个目录，减少命名冲突。
树形目录最常用，层次清晰。
无环图目录允许共享文件或目录，但不能有环。
通用图目录更灵活，但需要处理环路问题。
**背诵版**：目录结构：单级、二级、树形、无环图、通用图。现代系统常用树形目录。

### 问：文件磁盘分配方式有哪些？
答：连续分配、链接分配、索引分配。
连续分配把文件放在连续磁盘块中，顺序访问和随机访问都快，但容易产生外部碎片，文件扩展困难。
链接分配把文件块用指针链接起来，不需要连续空间，扩展方便，但随机访问慢，指针损坏风险大。
索引分配为每个文件建立索引块，索引块中保存文件所有数据块地址，随机访问方便，但需要额外索引空间。
**背诵版**：连续分配：访问快，但有外部碎片，扩展难。链接分配：扩展方便，但随机访问慢。索引分配：随机访问方便，但有索引开销。

### 问：Unix 文件系统的 inode 是什么？
答：inode 是 Unix/Linux 文件系统中保存文件元数据的数据结构。它记录文件大小、权限、拥有者、时间戳、数据块地址等信息。
文件名不在 inode 里，文件名保存在目录项中。目录项把文件名映射到 inode 编号。
**背诵版**：inode 保存文件元数据和数据块地址；目录项保存文件名到 inode 的映射。

## 16. 进程饥饿原因
### 问：什么是进程饥饿？
答：进程饥饿是指某个进程长期得不到所需资源或 CPU，导致一直无法向前推进。
饥饿不等于死锁。死锁是一组进程互相等待，谁都不能继续；饥饿是某个进程一直被别人插队或一直得不到资源。
**背诵版**：饥饿是进程长期得不到资源或 CPU，无法继续执行。死锁是互相等待；饥饿是长期等不到。

### 问：进程饥饿的原因有哪些？
答：第一，优先级调度中低优先级进程可能一直被高优先级进程抢占。
第二，SJF 或 SRTF 中长作业可能一直被短作业插队。
第三，资源分配不公平，某些进程总是拿不到资源。
第四，读者优先的读写者问题中，写者可能长期等待。
第五，锁竞争激烈时，某些线程可能一直抢不到锁。
**背诵版**：饥饿原因：优先级过低、短作业插队、资源分配不公平、锁竞争不公平。

### 问：如何解决饥饿？
答：可以使用老化机制，让等待时间越长的进程优先级逐渐升高。
也可以使用公平队列，按到达顺序分配资源。
还可以限制高优先级进程连续占用资源的时间，避免低优先级进程永远得不到运行。
**背诵版**：解决饥饿：老化机制、公平队列、限制长期占用。

## 17. 操作系统启动过程
### 问：计算机从开机到操作系统运行经历了什么？
答：大致过程是：通电后 CPU 从固定地址开始执行 BIOS 或 UEFI 固件。固件进行硬件自检，初始化基本硬件，然后找到启动设备。接着加载引导程序 Bootloader。Bootloader 再加载操作系统内核到内存。内核初始化内存管理、进程管理、设备驱动、文件系统等模块。最后启动第一个用户态进程，系统进入正常运行状态。
**背诵版**：开机启动过程：上电 → BIOS/UEFI → 硬件自检 → 找启动设备 → 加载 Bootloader → 加载内核 → 初始化内核 → 启动第一个用户进程。

### 问：BIOS/UEFI 的作用是什么？
答：BIOS/UEFI 是主板固件，负责开机后的硬件初始化、自检和启动引导。它会找到可启动设备，并把控制权交给引导程序。
**背诵版**：BIOS/UEFI 负责硬件初始化和寻找启动设备。

### 问：Bootloader 的作用是什么？
答：Bootloader 是引导加载程序，负责把操作系统内核加载到内存，并把控制权交给内核。常见 Bootloader 有 GRUB。
**背诵版**：Bootloader 负责加载操作系统内核。

### 问：内核启动后做什么？
答：内核启动后会初始化中断、内存管理、进程管理、设备驱动、文件系统，然后创建第一个用户态进程。
在 Linux 中，第一个用户态进程通常是 init 或 systemd。
**背诵版**：内核启动后初始化系统资源，并启动第一个用户态进程。

## 18. 何时用进程？何时用线程？
### 问：什么时候适合用进程？
答：当任务之间需要强隔离、互不影响、安全性要求高，或者一个任务崩溃不能影响其他任务时，适合使用进程。
例如浏览器的不同标签页可以用多进程，这样某个页面崩溃不容易拖垮整个浏览器。
**背诵版**：需要强隔离、高可靠、安全性高时，用进程。

### 问：什么时候适合用线程？
答：当多个任务属于同一个应用，需要频繁共享数据，并且希望创建和切换开销小，就适合使用线程。
例如一个程序中，一个线程负责界面显示，一个线程负责网络请求，一个线程负责后台计算。
**背诵版**：需要共享数据、切换开销小、并发执行同一任务时，用线程。

### 问：进程和线程在实际选择上怎么判断？
答：如果更重视隔离性和稳定性，选进程。
如果更重视共享数据和执行效率，选线程。
如果任务之间几乎不共享数据，适合进程。
如果任务之间需要频繁访问共同数据，适合线程。
**背诵版**：隔离性优先，用进程；效率和共享优先，用线程。
