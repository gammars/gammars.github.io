## 1. 什么是冯·诺依曼体系结构？

冯·诺依曼体系结构的核心思想是**存储程序**。

程序和数据都以二进制形式存放在存储器中，CPU 从存储器中依次取出指令并执行。

计算机主要由五部分组成：

- 运算器
    
- 控制器
    
- 存储器
    
- 输入设备
    
- 输出设备
    

其中运算器和控制器通常合称 CPU。

---

## 2. 为什么计算机采用补码表示有符号整数？

主要有三个原因。

第一，补码可以把减法转换成加法。

例如：

$A-B=A+(-B)$

这样 CPU 不需要单独设计一套减法器。

第二，补码中正数和负数可以使用同一套加法电路进行运算。

第三，补码中 0 只有一种表示方式。

原码中存在：

$+0$

和

$-0$

而补码中只有一个 0，因此能够多表示一个负数。

所以 $n$ 位补码的范围是：

$-2^{n-1}\sim 2^{n-1}-1$

---

## 3. 补码加法如何判断溢出？

只有以下两种情况会发生有符号溢出：

- 两个正数相加，结果变成负数；
    
- 两个负数相加，结果变成正数。
    

本质上是：

> 两个操作数符号相同，但结果符号与它们不同。

例如 8 位补码：

$127+1$

结果变成：

$10000000$

这个比特模式表示 $-128$，因此发生了溢出。

---

## 4. CF 和 OF 有什么区别？

CF 是 Carry Flag，进位标志，主要用于**无符号数运算**。

OF 是 Overflow Flag，溢出标志，主要用于**有符号数运算**。

例如：

```text
11111111 + 00000001
```

如果按无符号数：

$255+1=256$

超过 8 位表示范围，因此 CF = 1。

但是如果按有符号补码：

$-1+1=0$

没有溢出，因此 OF = 0。

所以：

> CF 看无符号溢出，OF 看有符号溢出。

---

## 5. 为什么浮点数不能精确表示 0.1？

因为计算机使用二进制。

十进制中的：

$0.1$

转换成二进制后是一个无限循环小数。

类似于十进制中：

$\frac{1}{3}=0.333333\cdots$

计算机只能保存有限位，因此只能保存一个近似值。

所以：

```python
0.1 + 0.2
```

得到的内部结果并不恰好等于 0.3。

这属于**浮点数表示误差**。

---

## 6. IEEE 754 单精度浮点数怎么表示？

IEEE 754 单精度浮点数一共 32 位：

- 1 位符号位
    
- 8 位指数
    
- 23 位尾数
    

结构为：

```text
S | exponent | fraction
1     8          23
```

数值大致表示为：

$(-1)^S\times 1.F\times 2^{E-127}$

其中指数使用偏置编码，单精度偏置值为 127。

尾数最高位通常是 1，因此 IEEE 754 不需要真的存这个 1，这叫**隐藏位**。

因此 23 位尾数字段实际上可以提供约 24 位有效二进制精度。

---

# 7. SRAM 和 DRAM 有什么区别？

SRAM 使用触发器保存数据，不需要刷新。

DRAM 使用电容保存数据，因为电容会漏电，所以需要定期刷新。

主要区别：

|SRAM|DRAM|
|---|---|
|快|较慢|
|不需要刷新|需要刷新|
|成本高|成本低|
|密度低|密度高|
|常用于 Cache|常用于主存|

所以：

> Cache 通常使用 SRAM，因为追求速度；主存使用 DRAM，因为追求容量和成本。

---

# 8. 为什么不能全部使用 SRAM 做内存？

理论上可以，但成本太高。

SRAM 每个存储单元通常需要多个晶体管，而 DRAM 一个存储单元可以用一个晶体管加一个电容实现。

因此 SRAM：

- 面积更大
    
- 功耗更高
    
- 成本更高
    

如果把几十 GB 内存全部做成 SRAM，价格和芯片面积都会非常夸张。

所以计算机采用存储层次结构：

```text
寄存器
↓
Cache
↓
主存
↓
SSD / 磁盘
```

越往上越快、越贵、容量越小。

---

# 9. 为什么需要 Cache？

因为 CPU 的速度远远快于主存。

如果每条指令都直接访问 DRAM，CPU 会大量时间处于等待状态。

所以在 CPU 和主存之间增加一层速度更快的 Cache。

Cache 能有效工作的核心原因是：

> 程序具有局部性。

---

# 10. 什么是局部性原理？

局部性主要分两种。

### 时间局部性

一个数据刚刚被访问，那么它在不久之后很可能再次被访问。

例如：

```c
for (...)
    sum += x;
```

变量 `sum` 会被反复访问。

### 空间局部性

访问一个地址后，很可能很快访问附近地址。

例如：

```c
for (int i = 0; i < 1000; i++)
    sum += a[i];
```

数组元素连续存放，因此访问 `a[0]` 后，很可能访问 `a[1]`、`a[2]`。

Cache 正是利用了这种规律。

---

# 11. 什么是 Cache Line？

Cache 并不是每次只从内存读取一个字节。

而是一次搬运一整块连续数据。

这一块通常叫：

> Cache Line，也叫 Cache Block。

例如 Cache Line 大小为 64B。

CPU 读取某个地址时，可能会把该地址附近的 64B 数据一起加载到 Cache。

这就是利用空间局部性。

---

# 12. Cache 有哪三种映射方式？

主要有：

### 直接映射

一个主存块只能放到 Cache 中唯一一个位置。

优点：

- 硬件简单
    
- 查找速度快
    

缺点：

- 容易产生冲突。
    

---

### 全相联映射

一个主存块可以放到 Cache 的任意位置。

优点：

- 冲突最少。
    

缺点：

- 查找复杂，需要同时比较很多 Tag。
    

---

### 组相联映射

先确定组，然后块可以放到该组中的任意一路。

例如：

> 4-way set associative

表示每组有 4 个 Cache Line。

这是直接映射和全相联之间的折中，也是现代 CPU 常见方案。

---

# 13. Cache 地址为什么要分成 Tag、Index、Offset？

一个内存地址通常可以拆成：

```text
Tag | Index | Offset
```

### Offset

确定数据位于一个 Cache Line 内的哪个位置。

### Index

确定应该查 Cache 的哪一组。

### Tag

确定这一组中的数据到底是不是我们需要的那个内存块。

所以访问流程是：

> Index 找组 → 比较 Tag → Offset 找具体字节。

---

# 14. Cache Miss 有哪几种？

经典有三种。

### Compulsory Miss

第一次访问某个数据，Cache 中必然没有。

也叫冷启动 Miss。

### Capacity Miss

Cache 总容量太小。

即使不存在映射冲突，也装不下工作集。

### Conflict Miss

多个不同内存块映射到了同一个 Cache 位置或同一组。

即使 Cache 还有其他空闲空间，也可能发生冲突。

一句话：

> 第一次访问：Compulsory  
> Cache 太小：Capacity  
> 映射打架：Conflict

---

# 15. Write Through 和 Write Back 有什么区别？

### Write Through

CPU 修改 Cache 时，同时修改主存。

优点：

> Cache 和主存始终一致。

缺点：

> 每次写都访问内存，慢。

---

### Write Back

CPU 修改 Cache 时暂时只修改 Cache。

等这个 Cache Line 被替换出去时，再写回主存。

因此需要一个：

> Dirty Bit。

Dirty Bit = 1 表示：

> Cache 中的数据已经被修改，但主存还没有更新。

Write Back 性能通常更好。

---

# 16. 为什么需要虚拟内存？

虚拟内存主要解决三个问题。

第一，为每个进程提供独立的地址空间。

每个进程都可以认为自己拥有完整的地址空间。

第二，实现内存保护。

不同进程不能随便访问其他进程的内存。

第三，让程序可以使用比实际物理内存更大的地址空间。

没有立即使用的页面可以暂时放在磁盘上。

因此程序使用的是：

> Virtual Address。

真正 DRAM 中使用的是：

> Physical Address。

---

# 17. 什么是页和页框？

虚拟地址空间被划分成固定大小的块，叫：

> Page，页。

物理内存也划分成相同大小的块，叫：

> Page Frame，页框。

操作系统负责建立：

虚拟页 $\rightarrow$ 物理页框

的映射。

这个映射记录在页表中。

---

# 18. 什么是页表？

页表负责记录：

> 虚拟页号 VPN → 物理页框号 PFN

CPU 得到虚拟地址后，需要通过页表进行地址转换。

虚拟地址可以看成：

```text
虚拟页号 | 页内偏移
```

查页表之后得到：

```text
物理页框号 | 页内偏移
```

从而形成物理地址。

---

# 19. 为什么需要 TLB？

如果每次访问内存之前都先访问页表：

第一步：

> 查页表。

第二步：

> 再访问真正的数据。

这样一次访存就可能变成两次甚至更多次访存。

因此 CPU 增加 TLB。

TLB 可以理解为：

> 页表的 Cache。

它缓存最近使用的虚拟页到物理页的映射。

因此大多数情况下可以直接从 TLB 中得到地址转换结果。

---

# 20. TLB 和 Cache 有什么区别？

TLB 缓存的是：

> 虚拟地址 → 物理地址的映射。

Cache 缓存的是：

> 真正的数据或指令。

所以：

```text
TLB：缓存地址翻译
Cache：缓存数据
```

二者作用完全不同。

---

# 21. 什么是 Page Fault？

CPU 访问某个虚拟页面时，发现这个页面当前不在物理内存中。

此时产生：

> Page Fault，缺页异常。

操作系统会：

1. 暂停当前程序；
    
2. 找一个可用物理页框；
    
3. 必要时淘汰其他页面；
    
4. 从磁盘把需要的页面读入内存；
    
5. 修改页表；
    
6. 重新执行刚才的指令。
    

由于涉及磁盘 I/O，Page Fault 的开销非常大。

---

# 22. Cache Miss 和 Page Fault 有什么区别？

Cache Miss 是：

> 数据不在 Cache，但通常还在主存。

所以只需要：

主存 $\rightarrow$ Cache

Page Fault 是：

> 页面甚至不在主存，需要从磁盘读入。

所以：

磁盘 $\rightarrow$ 主存

磁盘比内存慢很多，所以 Page Fault 代价远大于 Cache Miss。

---

# 23. PC 是什么？

PC 是 Program Counter，程序计数器。

作用是：

> 保存下一条将要执行的指令地址。

正常情况下，CPU 取完一条指令后：

$PC\leftarrow PC+\text{instruction length}$

如果遇到 branch、jump、call 等指令，则 PC 会被修改成新的目标地址。

---

# 24. IR 是什么？

IR 是 Instruction Register，指令寄存器。

CPU 从主存取出指令之后，会把当前正在执行的指令保存到 IR 中。

控制器根据 IR 中的 opcode 进行译码，判断这是什么指令。

所以：

> PC 保存“下一条指令在哪里”。

> IR 保存“当前执行什么指令”。

---

# 25. MAR 和 MDR 是什么？

MAR：

> Memory Address Register，存储器地址寄存器。

保存当前准备访问的内存地址。

MDR：

> Memory Data Register，存储器数据寄存器。

保存 CPU 和主存之间正在传输的数据。

例如读取：

```text
MAR ← 地址
MDR ← Memory[MAR]
```

写入则：

```text
MAR ← 地址
MDR ← 数据
Memory[MAR] ← MDR
```

---

# 26. CPU 如何取一条指令？

典型取指过程：

第一步：

$MAR\leftarrow PC$

把 PC 中的指令地址送到 MAR。

第二步：

$MDR\leftarrow M[MAR]$

从内存读取指令。

第三步：

$IR\leftarrow MDR$

把指令送入 IR。

同时更新：

$PC\leftarrow PC+\text{instruction length}$

然后控制器对 IR 中的指令进行译码。

---

# 27. 一条指令大致经历什么过程？

经典过程是：

> 取指 → 译码 → 执行 → 访存 → 写回。

在经典五级流水线中表示为：

```text
IF → ID → EX → MEM → WB
```

其中：

- IF：Instruction Fetch，取指
    
- ID：Instruction Decode，译码
    
- EX：Execute，执行
    
- MEM：Memory，访存
    
- WB：Write Back，写回
    

不同指令不一定真的需要所有阶段。

例如加法指令通常不需要访问数据内存。

---

# 28. 什么是流水线？

流水线就是：

> 让多条指令重叠执行。

例如当指令 1 正在 EX 阶段时：

- 指令 2 可以在 ID；
    
- 指令 3 可以在 IF。
    

所以多个流水阶段同时工作。

它类似工厂流水线。

关键点：

> 流水线主要提高吞吐率，而不是显著降低单条指令本身的延迟。

---

# 29. 流水线为什么不能无限加深？

理论上流水级越多，每一级逻辑越简单，可以提高时钟频率。

但流水线过深也有代价。

第一，每一级都需要流水寄存器，会产生额外延迟。

第二，发生分支预测错误时，要清空更多流水级。

第三，数据相关可能导致更多 stall。

第四，控制逻辑越来越复杂。

所以流水级数存在折中，不是越多越好。

---

# 30. 什么是结构冒险？

结构冒险是：

> 两条指令同时需要同一个硬件资源。

例如只有一个存储器。

某个周期中：

- 一条指令 MEM 阶段需要访问数据；
    
- 另一条指令 IF 阶段需要取指。
    

二者同时需要存储器，因此产生冲突。

解决方法包括：

- 增加硬件资源；
    
- 暂停其中一条指令。
    

现代 CPU 通常使用独立的指令 Cache 和数据 Cache，也能减少这种冲突。

---

# 31. 什么是数据冒险？

后一条指令依赖前一条指令的结果，但结果还没有准备好。

例如：

```asm
ADD R1, R2, R3
SUB R4, R1, R5
```

第二条指令需要 R1。

但第一条 ADD 的结果可能还没写回寄存器。

这就是数据冒险。

最常见的是：

> RAW：Read After Write。

也就是后一条指令想读，但前一条还没写完。

---

# 32. 什么是 Forwarding？

Forwarding 中文叫：

> 数据前递 / 数据旁路。

正常情况下，一条指令产生结果后可能要等到 WB 阶段才写回寄存器。

但下一条指令可能已经需要这个结果。

因此可以直接把 EX 或 MEM 阶段产生的结果送给下一条指令。

也就是：

> 不等写回寄存器，直接把结果传过去。

这样可以减少流水线停顿。

---

# 33. 为什么 Load-Use Hazard 即使有 Forwarding 也可能需要暂停？

例如：

```asm
LOAD R1, 0(R2)
ADD  R3, R1, R4
```

LOAD 的数据真正从内存读出来，要到 MEM 阶段结束后才得到。

但下一条 ADD 在 EX 阶段就已经需要 R1。

数据产生得太晚了。

所以即使存在 forwarding，也赶不上。

因此通常需要插入一个：

> bubble / stall。

---

# 34. 什么是控制冒险？

控制冒险主要来自：

> branch 和 jump。

CPU 在取到分支指令时，可能还不知道下一条到底应该取：

```text
PC + 4
```

还是：

```text
branch target
```

如果等分支结果出来再取指，CPU 会浪费多个周期。

因此现代 CPU 使用：

> Branch Prediction，分支预测。

先猜哪条路径会执行。

猜对了继续执行。

猜错了，则清空错误路径上的指令并重新取指。

---

# 35. 什么是硬布线控制器？

硬布线控制器使用组合逻辑电路直接产生各种控制信号。

例如根据：

- opcode
    
- 当前状态
    
- 标志位
    

直接决定：

- 哪个寄存器读；
    
- 哪个寄存器写；
    
- ALU 做什么运算；
    
- 是否访问内存。
    

优点：

> 快。

缺点：

> 电路复杂，不容易修改。

---

# 36. 什么是微程序控制器？

微程序控制器把一条机器指令进一步拆成若干条：

> 微指令。

每条微指令产生一组底层控制信号。

这些微指令构成微程序，存放在：

> 控制存储器。

优点：

- 设计简单；
    
- 容易修改；
    
- 容易实现复杂指令。
    

缺点：

> 比硬布线控制慢一些。

---

# 37. RISC 和 CISC 有什么区别？

RISC：

> Reduced Instruction Set Computer。

强调简单、规整的指令。

例如：

- ARM
    
- RISC-V
    

特点包括：

- 指令相对简单；
    
- 指令长度规整；
    
- Load/Store 架构；
    
- 寄存器较多；
    
- 更容易流水线。
    

CISC：

> Complex Instruction Set Computer。

典型代表是 x86。

特点：

- 指令种类更多；
    
- 指令长度可能不同；
    
- 一条指令可能完成复杂操作。
    

不过现代 CPU 内部已经非常复杂。

例如现代 x86 CPU 往往会把复杂 x86 指令翻译成内部更简单的微操作执行。

所以现在 RISC 和 CISC 的界限没有早期那么绝对。

---

# 38. 什么是中断？

中断是：

> 外部设备或系统事件通知 CPU 暂停当前程序，转而处理某件事情。

例如：

- 键盘输入；
    
- 网卡收到数据；
    
- 磁盘 I/O 完成；
    
- 时钟中断。
    

CPU 不需要不断查询设备状态。

设备有事情时主动通知 CPU。

---

# 39. 中断处理过程是什么？

典型过程：

1. CPU 执行完当前指令；
    
2. 检查是否有中断请求；
    
3. 保存当前程序现场；
    
4. 获得中断服务程序地址；
    
5. 跳转到中断服务程序；
    
6. 处理中断；
    
7. 恢复原程序现场；
    
8. 返回继续执行。
    

需要保存的内容通常至少包括：

- PC；
    
- 程序状态；
    
- 必要的寄存器。
    

---

# 40. 中断和异常有什么区别？

中断通常来自 CPU 外部，而且一般是异步的。

例如：

> 键盘、网卡、定时器。

异常通常由当前正在执行的指令引起，是同步的。

例如：

- 除零；
    
- Page Fault；
    
- 非法指令；
    
- 访问权限错误。
    

简单记：

> Interrupt：外面找 CPU。

> Exception：CPU 执行指令过程中自己出了事情。

---

# 41. 程序查询、中断和 DMA 有什么区别？

### 程序查询

CPU 不断查询设备：

> “好了吗？”

这种方式简单，但浪费 CPU 时间。

### 中断

设备完成工作之后通知 CPU。

CPU 可以先去做别的事情。

### DMA

DMA Controller 可以直接在：

设备 $\leftrightarrow$ 主存

之间搬运大量数据。

CPU 不需要逐字节参与。

所以数据量较大时：

> DMA 效率最高。

# 42. DMA 为什么效率高？

假设磁盘要把 1MB 数据传到内存。

如果完全依靠 CPU，CPU 可能需要重复执行：

```text
读取设备
写入内存
读取设备
写入内存
...
```

非常浪费 CPU。

使用 DMA 后，CPU 只需要告诉 DMA：

- 数据在哪；
    
- 要传到哪；
    
- 长度多少。
    

然后 DMA Controller 自己搬。

传输完成后再通过中断通知 CPU。

因此：

> CPU 负责“安排任务”，DMA 负责“搬数据”。

# 43. 什么是总线？

总线是计算机各部件之间共享的信息传输通道。

通常分为：

### 地址总线

告诉其他设备：

> 我要访问哪个地址。

### 数据总线

真正传输：

> 数据。

### 控制总线

传输：

- 读；
    
- 写；
    
- 中断；
    
- 时钟；
    
- 响应等控制信号。
    

---

# 44. 地址总线宽度决定什么？

如果地址总线有 $n$ 位，那么最多可以表示：

$2^n$

个不同地址。

如果系统按字节编址，那么理论最大地址空间就是：

$2^n\text{ Byte}$

例如 32 位地址：

$2^{32}\text{ Byte}=4\text{ GB}$

注意：

> 地址总线宽度决定的是地址空间，不等于机器一定真的安装了这么多物理内存。

---

# 45. 数据总线宽度决定什么？

数据总线宽度表示 CPU 一次可以在总线上传输多少位数据。

例如 64 位数据总线：

> 一次最多可以传输 64 bit，也就是 8 Byte。

所以数据总线越宽，理论上一拍可以搬的数据越多。

但系统实际带宽还受到：

- 总线频率；
    
- 协议；
    
- 内存；
    
- 控制器
    

等因素影响。

# 46. 为什么程序计数器 PC 不一定每次都加 1？

因为“加 1”取决于机器如何定义地址和指令长度。

例如按字节编址，且指令长度是 4B：

$PC\leftarrow PC+4$

并不是 +1。

另外遇到：

- branch
    
- jump
    
- call
    
- return
    
- interrupt
    

时，PC 还可能直接被写成另一个地址。

所以更准确地说：

> PC 默认指向下一条顺序执行指令，但控制流指令可以修改 PC。

# 47. 主频越高，CPU 一定越快吗？

不一定。

CPU 执行时间近似为：

$T=\frac{IC\times CPI}{f}$

其中：

- $IC$：指令数量
    
- $CPI$：平均每条指令需要几个周期
    
- $f$：时钟频率
    

主频提高确实可以缩短时钟周期。

但是如果：

- CPI 更高；
    
- Cache miss 更多；
    
- 分支预测更差；
    
- 指令数量更多；
    

整体性能仍然可能更差。

所以不能只看 GHz 判断 CPU 性能。

# 48. CPI 是什么？

CPI：

> Cycles Per Instruction。

表示平均执行一条指令需要多少个时钟周期。

例如一个程序执行了：

$10^9$

条指令，总共用了：

$2\times10^9$

个周期。

那么：

$CPI=2$

CPI 越低，一般说明每条指令消耗的周期越少。

---

# 49. IPC 是什么？

IPC：

> Instructions Per Cycle。

表示每个时钟周期平均可以完成多少条指令。

粗略情况下：

$IPC\approx\frac{1}{CPI}$

但现代超标量、乱序 CPU 中，定义和统计会更加复杂。

IPC 越高，通常意味着 CPU 能更充分地利用流水线和执行单元。

# 50. 什么是 Amdahl 定律？

Amdahl 定律说明：

> 优化整个系统中的某一个部分，最终加速比受到未优化部分的限制。

假设程序中 90% 可以加速无限倍。

还有 10% 永远不能优化。

那么整个程序最大加速比只有：

$\frac{1}{0.1}=10$

倍。
