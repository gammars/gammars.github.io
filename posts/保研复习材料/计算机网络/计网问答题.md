## 1. OSI七层模型 vs TCP/IP四层模型（各层功能、协议）
### OSI七层模型（自上而下）
1. **应用层**：为应用程序提供网络服务；协议：HTTP、DNS、FTP、SMTP
2. **表示层**：数据格式转换、加密解密、压缩解压
3. **会话层**：建立、管理、终止通信会话
4. **传输层**：**端到端（进程到进程）**通信；协议：TCP、UDP
5. **网络层**：**主机到主机**通信，寻址与路由；协议：IP、ARP
6. **数据链路层**：相邻节点传输，基于MAC地址；协议：以太网、PPP
7. **物理层**：传输比特流，完成比特与电/光/无线信号转换

### TCP/IP四层模型（自上而下）
1. **应用层**：合并OSI应用层、表示层、会话层
2. **传输层**：对应OSI传输层
3. **网际层（网络层）**：对应OSI网络层
4. **网络接口层**：合并OSI数据链路层、物理层

**总结**：OSI七层偏向理论标准；TCP/IP四层是工业实际实现。

## 2. 网络分层的原因与优点
通信系统复杂度极高，采用分层思想将复杂任务拆解。上层调用下层服务，下层屏蔽实现细节。
分层四大优点：
1. 降低问题复杂度；
2. 便于协议标准化，实现异构设备互通；
3. 层级独立，便于维护、迭代升级；
4. 故障分层定位，便于排错。

## 3. 单工、半双工、全双工通信
- **单工**：数据只能单向传输。例：广播、电视
- **半双工**：双方均可收发，但同一时刻仅一方发送。例：对讲机
- **全双工**：双方可同时收发数据。例：电话、交换式以太网

## 4. 网络协议三要素：语法、语义、时序
- **语法**：数据结构、格式（怎么传）
- **语义**：报文各字段含义（代表什么）
- **时序**：通信顺序、速率匹配（何时发送）

## 5. 香农公式（有噪声信道容量）
公式：$\boldsymbol{C=W\log_2(1+\(S/N\))}$
- $C$：信道容量(bit/s)；$W$：信道带宽(Hz)；$\(S/N\)$：信噪比
- 带宽越大、信噪比越高，信道最大传输速率越高
- 信噪比分贝转换：$\boldsymbol{\(S/N\)=10^{(dB/10)}}$

## 6. CSMA/CD 载波监听多路访问/冲突检测
适用：传统共享式半双工以太网
工作口诀：**先听再发，边发边听，冲突停止，随机重发**
流程：发送前监听信道；发送时持续检测冲突；检测冲突立即停止传输，发送干扰信号，等待随机时延重传。
> 交换式全双工以太网无需CSMA/CD。

## 7. TCP 与 UDP 对比（传输层）
共同点：基于端口实现进程通信。
| TCP | UDP |
| ---- | ---- |
| 面向连接，三次握手建立、四次挥手释放 | 无连接，无需建立连接 |
| 可靠传输：无丢失、无重复、有序交付 | 不可靠传输，可能丢包、乱序 |
| 面向字节流，无消息边界 | 面向报文，保留报文边界 |
| 头部≥20字节，开销大 | 头部固定8字节，开销小 |
| 适用：文件传输、网页、邮件（可靠性优先） | 适用：直播、语音、游戏、DNS（实时性优先） |

## 8. TCP 三次握手（建立连接）、四次挥手（释放连接）
### 三次握手
1. 客户端 → 服务端：`SYN` 请求建立连接
2. 服务端 → 客户端：`SYN+ACK` 同意连接，确认报文
3. 客户端 → 服务端：`ACK` 确认
作用：验证双方收发能力正常；阻止旧失效连接请求建立错误连接。

### 四次挥手
1. 主动关闭方 → 被动方：`FIN`，本方不再发送数据
2. 被动关闭方 → 主动方：`ACK`，收到关闭请求
3. 被动关闭方 → 主动方：`FIN`，本方数据发送完毕
4. 主动关闭方 → 被动方：`ACK`，连接正式释放
原因：TCP全双工通信，两个传输方向独立关闭；被动方可能仍有数据传输，`ACK`与`FIN`不能合并。

## 9. TCP、UDP头部结构
- **TCP头部**：最小20字节；包含源端口、目的端口、序号、确认号、窗口、标志位(SYN/ACK/FIN/RST/PSH/URG)、校验和、紧急指针。
- **UDP头部**：固定8字节；源端口、目的端口、报文长度、校验和。

## 10. TCP可靠传输五大机制
1. **序号**：字节编号，解决乱序、重复；
2. **确认ACK**：接收方反馈接收边界；
3. **超时重传**：未收到确认，自动重传；
4. **滑动窗口**：连续发送多段数据，提升吞吐量；
5. **校验和**：检测传输数据差错。

## 11. TCP拥塞控制四大算法（拥塞窗口cwnd）
1. **慢开始**：初始窗口较小，**指数增长**；到达`ssthresh`进入拥塞避免；
2. **拥塞避免**：窗口**线性缓慢增长**；
3. **快重传**：连续收到3个重复ACK，立即重传丢失报文；
4. **快恢复**：触发快重传时，`ssthresh=cwnd/2`，窗口降至ssthresh，直接进入拥塞避免。

区分：**超时重传**代表严重拥塞，cwnd重置为1，重新执行慢开始。

## 12. TCP 快速重传
无需等待超时计时器到期。接收方持续回复相同ACK；发送方收到**3个重复ACK**，判定报文丢失，立刻重传缺失报文，降低延迟。

## 13. 流量控制 vs 拥塞控制
- **流量控制**：防止**接收方缓冲区溢出**；依靠接收窗口`rwnd`；解决发送方和接收方速率匹配。
- **拥塞控制**：防止**网络路由器过载拥塞**；依靠拥塞窗口`cwnd`；解决全网负载。
发送窗口：$\boldsymbol{\(\boldsymbol{min(rwnd,cwnd)}\)}$

## 14. UDP报文无法接收排查思路
1. 发送端：目的IP、端口配置错误；报文未成功发出；
2. 网络层：路由不通、防火墙拦截、NAT策略限制；
3. 接收端：绑定地址错误（127.0.0.1仅本机访问）、端口占用；
4. 应用程序：无循环接收、缓冲区不足、接收线程阻塞。
补充：UDP本身无可靠性，报文丢失属于正常现象。

## 15. ARP & RARP
- **ARP**：网络层协议，**已知IP地址，查询MAC地址**；局域网广播请求，单播应答，维护ARP缓存。
- **RARP**：已知MAC地址查询IP地址；老式无盘工作站使用，现已被DHCP取代。

## 16. 网卡（网络适配器）功能
1. 数据帧收发；
2. 以太网帧封装与解封装；
3. 提供唯一MAC物理地址；
4. FCS差错检测；
5. 数字信号与物理传输信号（电/光）相互转换。

## 17. 跨主机通信核心流程
1. 判断目标IP是否与本机同网段：
    - 同网段：ARP查询**目标主机MAC**，直接交付；
    - 不同网段：ARP查询**网关MAC**，交付路由器转发。
2. 发送：逐层封装数据（应用→传输段→IP报文→数据帧）
3. 接收：逐层解封装（数据帧→IP报文→传输段→应用数据）

> 转发过程：**目的IP全程不变；每一跳目的MAC不断更新**。

## 18. 多端口能否提升吞吐量？
端口只是**逻辑标识**，不代表带宽上限。
- 瓶颈在连接数量、单链路带宽：多端口/链路聚合可提升吞吐；
- 瓶颈在CPU、磁盘IO、服务器性能、出口带宽：增加端口无效。
TCP四元组：源IP、源端口、目的IP、目的端口，区分连接。

## 19. DNS域名解析流程
查询顺序：浏览器缓存 → 操作系统缓存 → hosts文件 → 本地DNS服务器
本地DNS无缓存时迭代查询：根域名服务器 → 顶级域名服务器 → 权威域名服务器。
查询模式：主机 ↔ 本地DNS：**递归查询**；本地DNS ↔ 各级域名服务器：**迭代查询**。

## 20. 在浏览器输入网址，完整通信流程
1. 解析URL，提取协议、域名、路径；
2. DNS解析域名得到服务器IP；
3. 与服务器建立TCP三次握手；
4. HTTPS额外执行TLS握手，协商加密通道；
5. 浏览器发送HTTP请求；
6. 服务器处理请求，返回HTTP响应报文；
7. 浏览器解析HTML，并行请求页面内嵌资源(CSS/JS/图片)；
8. 浏览器渲染页面展示。

## 21. IP地址 vs MAC地址
- **IP地址（网络层）**：逻辑地址；标识主机网络位置；可变更；用于跨网段路由寻址；全程不变。
- **MAC地址（链路层）**：物理地址；固化于网卡；相对固定；用于局域网帧交付；每一跳发生改变。

## 22. HTTP状态码 & HTTP/HTTPS区别
### 状态码分类
- 1xx：信息响应
- 2xx：请求成功（200 OK）
- 3xx：重定向（301永久重定向、302临时重定向、304协商缓存）
- 4xx：客户端错误（404不存在、403禁止访问、401未认证）
- 5xx：服务端错误（500内部错误、502网关错误、503不可用）

### HTTP & HTTPS
HTTP：明文传输，默认80端口；存在窃听、篡改风险。
HTTPS = HTTP + TLS；默认443端口；提供**传输加密、身份认证、数据完整性校验**。

## 23. DHCP 动态主机配置协议
作用：自动为主机分配网络参数：IP地址、子网掩码、网关、DNS、地址租约。
工作流程 **DORA**
1. Discover：客户端广播寻找DHCP服务器
2. Offer：服务器提供可用IP地址
3. Request：客户端请求使用分配地址
4. ACK：服务器确认分配，客户端正式启用IP

## 24. 应用层能否直接交付网络层？
标准分层模型中**不允许**。
原因：网络层IP仅实现主机到主机交付；传输层依靠端口号实现**进程到进程通信**。绕过传输层，无法将数据交付主机内指定程序。
特殊情况：原始套接字Raw Socket可手动构造IP报文，属于特殊编程实现，不属于标准通信流程。

## 25. Socket 套接字
Socket是**应用程序与操作系统网络协议栈之间的编程接口**。
由【IP地址 + 端口 + 传输协议】标识通信端点。
- TCP：服务端创建Socket→绑定→监听→接受连接；客户端Socket主动建立连接；
- UDP：无连接通信，Socket绑定端口后直接收发报文。

## 26. Cookie vs Session
背景：HTTP无状态协议，二者用于维持会话状态。
- **Cookie**：存储在**客户端浏览器**；容量受限，可被篡改；减轻服务器存储压力。
- **Session**：数据存储在**服务器**；安全性更高；占用服务器资源；一般依靠Cookie保存SessionID。

## 27. 路由器功能（网络层设备）
1. **路由选择**：维护路由表，根据目的IP选择转发下一跳；
2. **分组转发**：将IP报文从对应接口转发；
3. **隔离广播域**，阻断跨网段广播报文；
家用路由器扩展能力：NAT地址转换、DHCP、防火墙、无线AP。
