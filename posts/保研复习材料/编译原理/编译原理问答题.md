# 1. 编译过程与 First / Follow 集合

## 1.1 什么是编译？

**一句话理解：**

编译就是把高级语言程序翻译成机器能够执行的低级语言程序。

**正式说法：**

编译是指将用高级程序设计语言编写的源程序，经过一系列分析和转换，翻译成目标程序的过程。目标程序可以是汇编代码、机器代码，也可以是某种中间代码。

**面试背诵版：**

编译是把高级语言源程序翻译成目标程序的过程。它通常包括词法分析、语法分析、语义分析、中间代码生成、代码优化和目标代码生成等阶段。


## 1.2 编译过程包括哪些阶段？

经典编译过程一般分为六个阶段：

1. 词法分析
2. 语法分析
3. 语义分析
4. 中间代码生成
5. 代码优化
6. 目标代码生成

除此之外，还有两个贯穿整个编译过程的重要部分：

- 符号表管理
- 错误处理

**面试背诵版：**

编译过程通常包括词法分析、语法分析、语义分析、中间代码生成、代码优化和目标代码生成六个阶段。其中符号表管理和错误处理贯穿整个编译过程。


## 1.3 词法分析做什么？

**一句话理解：**

词法分析就是把一串字符切成一个个单词。

例如源代码：
```c
int a = 10;
```
词法分析后可能得到：
- 关键字 `int`
- 标识符 `a`
- 赋值符号 `=`
- 整数常量 `10`
- 分号 `;`

**面试背诵版：**

词法分析是编译的第一个阶段，它从左到右扫描源程序字符流，识别出关键字、标识符、常量、运算符和界符等单词符号，并生成记号序列，也称为 Token 序列。

词法分析的输入是源程序字符流，输出是 Token 序列。


## 1.4 语法分析做什么？

**一句话理解：**

语法分析就是检查 Token 能不能按照语法规则组成合法句子。

例如：
```c
int a = ;
```
词法上每个单词都可能没问题，但是语法上不合法，因为等号后面缺少表达式。

**面试背诵版：**

语法分析根据语言的文法规则，对词法分析产生的 Token 序列进行结构分析，判断其是否符合语法规则，并构造语法树或分析树。

语法分析的输入是 Token 序列，输出是语法树、分析树，或者语法结构信息。


## 1.5 语义分析做什么？

**一句话理解：**

语义分析就是检查“语法正确的句子，意思是否合理”。

例如：
```c
int a;
a = "hello";
```
语法上可能能组成赋值语句，但语义上不合理，因为把字符串赋给整数变量。

**面试背诵版：**

语义分析检查源程序是否符合语义规则，包括类型检查、变量是否声明、函数参数是否匹配、作用域是否合法等，并为后续中间代码生成提供语义信息。


## 1.6 中间代码生成做什么？

**一句话理解：**

中间代码就是介于高级语言和机器语言之间的一种中间表示。

**常见中间代码形式：**

- 三地址码
- 四元式
- 抽象语法树
- 静态单赋值形式 SSA

例如：
```
a = b + c * d;
```
可能生成：
```
t1 = c * d
t2 = b + t1
a = t2
```

**面试背诵版：**

中间代码生成是将经过语义分析后的源程序转换为一种与具体机器无关的中间表示。中间代码便于进行优化，也便于移植到不同目标机器。


## 1.7 代码优化做什么？

**一句话理解：**

代码优化就是让程序运行更快、占空间更少，但不改变程序原本含义。

**常见优化：**

- 常量折叠
- 公共子表达式删除
- 死代码删除
- 循环优化
- 强度削弱
- 寄存器分配优化

例子：
```
x = 2 * 3;
```
可以优化为：
```
x = 6;
```

**面试背诵版：**

代码优化是在保持程序语义不变的前提下，对中间代码或目标代码进行改进，以提高程序的运行效率或减少存储空间。


## 1.8 目标代码生成做什么？

**一句话理解：**

目标代码生成就是把中间代码翻译成目标机器能执行的代码。

**面试背诵版：**

目标代码生成阶段将中间代码转换为目标机器上的汇编代码或机器代码，主要任务包括指令选择、寄存器分配和存储分配等。


## 1.9 符号表是什么？

**一句话理解：**

符号表就是编译器用来记录变量、函数、类型等信息的一张表。

例如变量：
```c
int age;
```
符号表中可能记录：
- 名字：age
- 类型：int
- 作用域：当前函数或全局
- 存储位置：某个地址或偏移量

**面试背诵版：**

符号表是编译过程中用于记录标识符相关信息的数据结构，包括变量名、类型、作用域、存储位置、函数参数等。符号表管理贯穿词法分析、语法分析、语义分析和代码生成等阶段。


## 1.10 错误处理是什么？

编译器需要发现并报告程序中的错误。

**常见错误：**

- 词法错误：非法字符
- 语法错误：语句结构不符合文法
- 语义错误：类型不匹配、变量未声明

**面试背诵版：**

错误处理贯穿编译全过程，用于发现、报告并尽可能恢复源程序中的词法错误、语法错误和语义错误，使编译器能够给出有意义的错误信息。


# 2. First / Follow 集合

## 2.1 First 集合是什么？

**一句话理解：**

First 集合表示一个符号串可能以哪些终结符开头。

**正式说法：**

对于文法符号串 $\alpha$，$FIRST(\alpha)$ 是从 $\alpha$ 能够推导出的所有串的首终结符集合。如果 $\alpha$ 能推出空串 $\varepsilon$，则 $\varepsilon$ 也属于 $FIRST(\alpha)$。

**面试背诵版：**

FIRST 集合表示某个文法符号或符号串能够推导出的句型中，可能出现在最左端的终结符集合。如果该符号串能推出空串，则 $\varepsilon$ 也属于 FIRST 集合。


## 2.2 Follow 集合是什么？

**一句话理解：**

Follow 集合表示某个非终结符后面可能跟哪些终结符。

**正式说法：**

对于非终结符 $A$，$FOLLOW(A)$ 是在某些句型中可能紧跟在 $A$ 后面的终结符集合。如果 $A$ 可能出现在句型末尾，则把输入结束符 `#` 或 `$` 加入 $FOLLOW(A)$。

**面试背诵版：**

FOLLOW 集合表示在某个文法的句型中，可能紧跟在非终结符后面的终结符集合。对于开始符号，通常将输入结束符 `#` 加入其 FOLLOW 集合。


## 2.3 First 集合怎么求？

**核心规则：**

1. 如果 $X$ 是终结符，那么：
   $$FIRST(X) = \{X\}$$

2. 如果 $X$ 是非终结符，并且有产生式 $X \rightarrow a...$，其中 $a$ 是终结符，则把 $a$ 加入 $FIRST(X)$。

3. 如果有产生式 $X \rightarrow \varepsilon$，则把 $\varepsilon$ 加入 $FIRST(X)$。

4. 如果有产生式 $X \rightarrow Y_1Y_2...Y_k$，则先把 $FIRST(Y_1)$ 中除 $\varepsilon$ 外的元素加入 $FIRST(X)$。如果 $Y_1$ 能推出空串，再继续看 $Y_2$，依次类推。

**速记：** First 看“开头”。能不能空，就往后看。


## 2.4 Follow 集合怎么求？

**核心规则：**

1. 开始符号的 Follow 集合加入结束符 `#`。

2. 如果有产生式 $A \rightarrow \alpha B \beta$，那么把 $FIRST(\beta)$ 中除 $\varepsilon$ 以外的符号加入 $FOLLOW(B)$。

3. 如果有产生式 $A \rightarrow \alpha B$，或者 $A \rightarrow \alpha B \beta$ 且 $\beta$ 能推出空串，则把 $FOLLOW(A)$ 加入 $FOLLOW(B)$。

**速记：** Follow 看“后面”。后面有东西，看后面东西的 First。后面没东西，或者后面能为空，就继承左边非终结符的 Follow。


## 2.5 First 和 Follow 有什么用？

它们主要用于构造预测分析表，判断文法是否为 LL(1) 文法，并指导自顶向下语法分析。

**面试背诵版：**

FIRST 和 FOLLOW 集合是语法分析中的重要工具，常用于构造 LL(1) 预测分析表。FIRST 集合用于判断当前输入符号可能选择哪个产生式，FOLLOW 集合用于处理产生式能推出空串时的选择问题。


# 3. 上下文无关文法特点

## 3.1 什么是文法？

**一句话理解：**

文法就是用来描述语言语法规则的一套规则。

一个文法通常表示为四元组：
$$G = (V_N, V_T, P, S)$$

其中：
- $V_N$：非终结符集合
- $V_T$：终结符集合
- $P$：产生式集合
- $S$：开始符号

**面试背诵版：**

文法是描述语言句子结构的形式化规则系统，通常由非终结符集合、终结符集合、产生式集合和开始符号组成。


## 3.2 什么是终结符？

终结符就是不能再继续推导的基本符号。

例如在程序语言中，关键字、标识符、运算符、界符、常量等都可以看作终结符。比如：`id`、`+`、`*`、`(`、`)`。


## 3.3 什么是非终结符？

非终结符是可以继续推导的语法变量。

例如：表达式、语句、函数定义、参数列表在文法中常用大写字母表示，如：$E$、$T$、$F$、$S$。


## 3.4 什么是产生式？

产生式就是推导规则。

形式一般是：
$$A \rightarrow \alpha$$

表示非终结符 $A$ 可以被替换成符号串 $\alpha$。

例如：
$$E \rightarrow E + T$$
表示表达式 $E$ 可以推导为表达式加项。


## 3.5 什么是上下文无关文法？

**一句话理解：**

上下文无关文法就是每条产生式左边只能有一个非终结符，不管它出现在什么上下文，都可以按这条规则替换。

**正式定义：**

若文法中所有产生式都满足：
$$A \rightarrow \alpha$$
其中 $A$ 是一个非终结符，$\alpha$ 是终结符和非终结符组成的符号串，则该文法称为上下文无关文法。

**面试背诵版：**

上下文无关文法是指产生式左部只含有一个非终结符的文法。它表示该非终结符的替换不依赖于其左右上下文，常用于描述程序设计语言的语法结构。


## 3.6 为什么叫“上下文无关”？

因为只要看到某个非终结符 $A$，就可以用产生式 $A \rightarrow \alpha$ 替换它，不需要看 $A$ 左边或右边是什么符号。

例如：
$$E \rightarrow E + T$$
只要出现 $E$，就可以按照规则展开，与它处于什么上下文无关。


## 3.7 上下文无关文法有什么特点？

1. 产生式左部只有一个非终结符
2. 适合描述嵌套结构
3. 常用于程序设计语言的语法分析
4. 能够描述括号匹配、表达式、语句块等结构
5. 通常由语法分析器处理

**面试背诵版：**

上下文无关文法的主要特点是产生式左部只有一个非终结符，因此替换规则不依赖上下文。它表达能力适中，特别适合描述程序设计语言中的递归和嵌套语法结构，如表达式、语句和括号匹配等。


## 3.8 上下文无关文法能描述什么？

常见可以描述：

- 算术表达式
- 条件语句
- 循环语句
- 函数调用
- 括号匹配
- 程序块嵌套

例如括号匹配文法：
$$S \rightarrow (S)S \mid \varepsilon$$
它可以生成合法括号串。


## 3.9 上下文无关文法和正则文法有什么区别？

正则文法表达能力较弱，通常用于描述词法结构。上下文无关文法表达能力更强，通常用于描述语法结构。

**面试背诵版：**

正则文法常用于词法分析，可以描述标识符、关键字、数字等词法单元；上下文无关文法常用于语法分析，可以描述表达式、语句、嵌套结构等更复杂的语法结构。


# 4. 0 型、1 型、2 型、3 型文法及其关系

这部分叫**乔姆斯基层次结构**，非常爱考。

## 4.1 四类文法分别是什么？

- **0 型文法**：短语结构文法，也叫无限制文法
- **1 型文法**：上下文有关文法
- **2 型文法**：上下文无关文法
- **3 型文法**：正规文法，也叫正则文法

它们的包含关系是：
$$\text{3型} \subset \text{2型} \subset \text{1型} \subset \text{0型}$$

也就是说：正规文法最弱，上下文无关文法更强，上下文有关文法更强，0 型文法最强。


## 4.2 0 型文法是什么？

0 型文法也叫短语结构文法或无限制文法。

产生式形式最宽松，一般为：
$$\alpha \rightarrow \beta$$
其中 $\alpha$ 至少含有一个非终结符。

**面试背诵版：**

0 型文法是限制最少、表达能力最强的文法，其产生式左部可以是包含非终结符的任意符号串。0 型文法对应图灵机可识别的语言。


## 4.3 1 型文法是什么？

1 型文法也叫上下文有关文法。

产生式通常满足：
$$\alpha A \beta \rightarrow \alpha \gamma \beta$$
其中 $\gamma$ 非空。

意思是：非终结符 $A$ 能否替换成 $\gamma$，要看它左右上下文 $\alpha$ 和 $\beta$。

**面试背诵版：**

1 型文法又称上下文有关文法，其产生式左部和右部可以包含上下文信息，且通常要求产生式右部长度不小于左部长度。它的替换规则依赖于非终结符所在的上下文。

**注意：** 除了特殊情况 $S \rightarrow \varepsilon$，1 型文法一般不允许产生式右部比左部短。


## 4.4 2 型文法是什么？

2 型文法就是上下文无关文法。

产生式形式为：
$$A \rightarrow \alpha$$
其中 $A$ 是单个非终结符。

**面试背诵版：**

2 型文法又称上下文无关文法，其产生式左部只能是一个非终结符，右部是任意符号串。它常用于描述程序设计语言的语法结构。


## 4.5 3 型文法是什么？

3 型文法也叫正规文法或正则文法。

它的产生式有严格限制，通常分为右线性文法和左线性文法。

**右线性文法形式：**
$$A \rightarrow aB \quad \text{或} \quad A \rightarrow a$$

**左线性文法形式：**
$$A \rightarrow Ba \quad \text{或} \quad A \rightarrow a$$

其中 $A,B$ 是非终结符，$a$ 是终结符。

**面试背诵版：**

3 型文法又称正规文法，产生式形式受限，通常为左线性或右线性。它对应正则语言，常用于词法分析，可以由有限自动机识别。


## 4.6 四类文法对应什么自动机？

| 文法类型 | 对应自动机 |
|---------|-----------|
| 0 型文法 | 图灵机 |
| 1 型文法 | 线性有界自动机 |
| 2 型文法 | 下推自动机 |
| 3 型文法 | 有限自动机 |

**速背版：**

- 3 型靠有限自动机
- 2 型靠下推自动机
- 1 型靠线性有界自动机
- 0 型靠图灵机


## 4.7 四类文法在编译原理中分别有什么用？

- **3 型文法**：常用于词法分析，例如标识符、数字、关键字等词法单元
- **2 型文法**：常用于语法分析，例如表达式、语句、程序结构
- **1 型和 0 型**：理论表达能力更强，但在普通编译器实现中不常直接使用

**面试背诵版：**

在编译原理中，正规文法主要用于词法分析，上下文无关文法主要用于语法分析。上下文有关文法和 0 型文法表达能力更强，但分析复杂度较高，因此实际编译器中较少直接使用。


## 4.8 四类文法关系怎么背？

**表达能力：**
$$\text{0型} > \text{1型} > \text{2型} > \text{3型}$$

**限制程度：**
$$\text{3型} > \text{2型} > \text{1型} > \text{0型}$$

也就是说：
- 越靠近 0 型，限制越少，表达能力越强，但越难分析
- 越靠近 3 型，限制越多，表达能力越弱，但越容易实现

**面试背诵版：**

乔姆斯基层次结构中，3 型文法包含于 2 型文法，2 型文法包含于 1 型文法，1 型文法包含于 0 型文法。文法编号越小，限制越少，表达能力越强；编号越大，限制越多，分析越容易。


# 5. 编译原理的词法分析过程

## 5.1 什么是词法分析？

词法分析是编译器的第一个阶段。它的任务是读取源程序字符流，识别出一个个单词符号 Token。

**面试背诵版：**

词法分析从左到右扫描源程序字符流，将字符序列转换成单词符号序列，同时过滤空白符、换行符和注释，并识别关键字、标识符、常量、运算符和界符等词法单元。


## 5.2 词法分析输入和输出是什么？

- **输入**：源程序字符流
- **输出**：Token 序列

每个 Token 一般包含两部分：
- 种别码
- 属性值

例如：
```c
int count = 10;
```
可能输出：
```
<关键字, int>
<标识符, count>
<赋值符, =>
<整数常量, 10>
<分号, ;>
```

**面试背诵版：**

词法分析的输入是源程序字符流，输出是 Token 序列。Token 通常由种别码和属性值组成，种别码表示单词类型，属性值表示具体内容或符号表入口。


## 5.3 词法分析识别哪些内容？

主要识别：

- **关键字**：如 if、else、while、int
- **标识符**：变量名、函数名
- **常量**：整数、浮点数、字符、字符串
- **运算符**：+、-、*、/、=、==
- **界符**：逗号、分号、括号、大括号

同时会跳过：
- 空格
- 换行
- 制表符
- 注释


## 5.4 词法分析的结果是什么？

词法分析的结果是 Token 序列，也叫记号流。这些 Token 会交给语法分析器继续处理。如果发现非法字符或不符合词法规则的单词，会报告词法错误。

**面试背诵版：**

词法分析的结果是单词符号序列，即 Token 序列。该序列作为语法分析阶段的输入。如果扫描过程中遇到非法字符或不合法单词，则产生词法错误。


## 5.5 词法分析器如何实现？

常见实现步骤：

1. 用正规式描述词法规则
2. 把正规式转换为 NFA
3. 把 NFA 转换为 DFA
4. 对 DFA 进行化简
5. 根据 DFA 编写词法分析程序

实际中也可以使用工具：Lex、Flex。

**面试背诵版：**

词法分析器通常用正规式描述单词符号的模式，再将正规式转换为有限自动机进行识别。理论上可以经历正规式到 NFA、NFA 到 DFA、DFA 最小化的过程，实际中也可以使用 Lex 或 Flex 等工具自动生成词法分析器。


## 5.6 为什么词法分析用正规式和有限自动机？

因为词法单元通常比较简单，可以用正则语言描述。

例如：
- 标识符：`字母(字母|数字)*`
- 整数：`数字+`

这些都可以用正规式表示，也能被有限自动机识别。

**面试背诵版：**

词法结构通常属于正则语言，能够用正规式描述，并能由有限自动机高效识别。因此词法分析常采用正规式和有限自动机实现。


# 6. 代码如何实现

这里一般面试不会让你完整手写编译器，但会问“词法分析器怎么写”“代码实现思路是什么”。

## 6.1 手写词法分析器的基本思路

可以按字符一个一个扫描。

**核心流程：**

1. 维护一个指针 `i`，从源代码开头开始扫描
2. 遇到空格、换行、注释，跳过
3. 遇到字母或下划线，识别关键字或标识符
4. 遇到数字，识别整数或浮点数
5. 遇到运算符，判断是一字符运算符还是双字符运算符
6. 遇到界符，直接生成 Token
7. 遇到非法字符，报错

**面试背诵版：**

手写词法分析器通常采用从左到右扫描的方法，根据当前字符类型进入不同识别分支：字母开头识别关键字或标识符，数字开头识别常量，符号开头识别运算符或界符，同时跳过空白符和注释，最终输出 Token 序列。


## 6.2 关键字和标识符怎么区分？

例如扫描到 `while`，它既符合标识符规则，又是关键字。

**处理方式：**

1. 先按照标识符规则扫描完整单词
2. 然后查关键字表
3. 如果在关键字表中，就是关键字；否则就是普通标识符

**面试背诵版：**

关键字和标识符通常先按标识符的词法规则统一识别，然后查关键字表。如果该字符串在关键字表中，则归类为关键字；否则归类为标识符。


## 6.3 运算符怎么识别？

要注意双字符运算符，例如：`==`、`<=`、`>=`、`!=`。

扫描到一个符号后，需要向后看一个字符。如果能组成双字符运算符，就优先识别双字符；否则识别单字符。

**面试背诵版：**

运算符识别通常采用最长匹配原则。扫描到运算符起始字符后，继续查看后续字符，尽可能匹配最长的合法运算符，例如优先识别 `==` 而不是两个单独的 `=`。


## 6.4 注释怎么处理？

- **单行注释**：`// comment` 跳过到行尾
- **多行注释**：`/* comment */` 跳过到 `*/`

**面试答法：**

词法分析阶段通常会过滤注释和空白符，它们一般不作为有效 Token 传给语法分析器。但它们可能用于记录行号，以便错误定位。


## 6.5 词法分析代码伪代码

```text
while 没有到达源程序末尾:
    读取当前字符 ch

    如果 ch 是空白符:
        跳过

    否则如果 ch 是字母或下划线:
        继续读取字母、数字、下划线
        得到字符串 word
        如果 word 在关键字表中:
            输出 <关键字, word>
        否则:
            输出 <标识符, word>

    否则如果 ch 是数字:
        继续读取数字
        如果遇到小数点，继续读取小数部分
        输出 <常量, value>

    否则如果 ch 是运算符:
        按最长匹配原则识别运算符
        输出 <运算符, op>

    否则如果 ch 是界符:
        输出 <界符, ch>

    否则:
        报告非法字符错误
```


# 7. 编译之前的过程有哪些？

这个问题容易理解错。它通常想问“从源文件到真正编译之前，预处理阶段做什么”。

以 C/C++ 为例，一个程序从源代码到可执行文件，一般经过：
1. 预处理
2. 编译
3. 汇编
4. 链接


## 7.1 预处理做什么？

预处理发生在真正编译之前。

主要处理：
- 宏展开
- 头文件包含
- 条件编译
- 删除注释

例如：
```c
#define PI 3.14
```
预处理会把代码中的 `PI` 替换成 `3.14`。

```c
#include <stdio.h>
```
预处理会把头文件内容引入当前文件。

**面试背诵版：**

预处理是编译之前的阶段，主要完成宏展开、头文件包含、条件编译和注释删除等工作，生成经过预处理后的源程序。


## 7.2 编译做什么？

狭义编译通常是把预处理后的源程序翻译成汇编代码。

它包括：
- 词法分析
- 语法分析
- 语义分析
- 中间代码生成
- 优化
- 生成汇编代码

**面试答法：**

编译阶段将预处理后的高级语言程序进行词法、语法和语义分析，并经过中间代码生成和优化，最终生成汇编代码。


## 7.3 汇编做什么？

汇编是把汇编代码转换成机器指令，生成目标文件。

例如：`test.s -> test.o`

**面试背诵版：**

汇编阶段将编译生成的汇编代码转换成机器指令，生成可重定位目标文件。


## 7.4 链接做什么？

链接是把多个目标文件和库文件合并成一个可执行文件。

例如：`main.o + add.o + libc -> a.out`

链接器会解决函数和变量地址问题。

**面试背诵版：**

链接阶段将多个目标文件以及所需库文件合并，解析外部符号引用，完成地址重定位，最终生成可执行文件。


## 7.5 C/C++ 从源代码到可执行文件完整流程

**速背：**

源程序 → 预处理 → 编译 → 汇编 → 链接 → 可执行文件

**面试背诵版：**

以 C/C++ 程序为例，从源代码到可执行文件一般要经过预处理、编译、汇编和链接四个阶段。预处理负责宏展开、头文件展开和条件编译；编译负责把高级语言代码翻译为汇编代码；汇编负责生成目标文件；链接负责合并目标文件和库文件，生成最终可执行程序。


# 8. 编译原理常见面试问题与标准回答

## 问题 1：编译器的主要阶段有哪些？

**答：**

编译器主要包括词法分析、语法分析、语义分析、中间代码生成、代码优化和目标代码生成六个阶段。词法分析把字符流转换为 Token 序列，语法分析根据文法规则构造语法结构，语义分析检查类型和作用域等语义信息，中间代码生成得到机器无关的中间表示，代码优化提高程序效率，目标代码生成最终得到汇编代码或机器代码。此外，符号表管理和错误处理贯穿整个编译过程。


## 问题 2：词法分析和语法分析有什么区别？

**答：**

词法分析关注的是字符能否组成合法单词，输出 Token 序列；语法分析关注的是 Token 序列能否按照文法规则组成合法语法结构，输出语法树或分析树。简单来说，词法分析检查“单词对不对”，语法分析检查“句子结构对不对”。


## 问题 3：语法分析和语义分析有什么区别？

**答：**

语法分析检查程序结构是否符合文法规则，例如括号是否匹配、语句结构是否完整；语义分析检查语法正确的程序是否具有合理含义，例如变量是否声明、类型是否匹配、函数参数个数是否正确。语法正确不代表语义一定正确。


## 问题 4：First 集合和 Follow 集合有什么用？

**答：**

FIRST 集合表示某个文法符号串可能推导出的首终结符集合，FOLLOW 集合表示某个非终结符后面可能紧跟的终结符集合。它们常用于构造 LL(1) 预测分析表，帮助语法分析器根据当前非终结符和输入符号选择合适的产生式。


## 问题 5：什么是上下文无关文法？

**答：**

上下文无关文法是产生式左部只有一个非终结符的文法，形式为 $A \rightarrow \alpha$。它表示非终结符的替换不依赖左右上下文，常用于描述程序设计语言中的表达式、语句和嵌套结构。


## 问题 6：0 型、1 型、2 型、3 型文法的关系是什么？

**答：**

乔姆斯基层次结构中，3 型文法属于 2 型文法，2 型文法属于 1 型文法，1 型文法属于 0 型文法。也就是说：
$$\text{3型} \subset \text{2型} \subset \text{1型} \subset \text{0型}$$

其中 3 型是正规文法，常用于词法分析；2 型是上下文无关文法，常用于语法分析；1 型是上下文有关文法；0 型是无限制文法，表达能力最强。


## 问题 7：为什么词法分析通常用正规式和有限自动机？

**答：**

因为词法单元如标识符、关键字、数字、运算符等结构相对简单，通常可以用正则语言描述，而正则语言可以由有限自动机识别。因此词法分析常用正规式定义词法规则，并通过有限自动机实现高效扫描。


## 问题 8：Token 一般包含什么？

**答：**

Token 一般包含种别码和属性值。种别码表示该单词属于哪一类，例如关键字、标识符、常量、运算符或界符；属性值保存该单词的具体信息，例如标识符名字、常量值，或者符号表入口。


## 问题 9：C 程序从源代码到可执行文件经历哪些阶段？

**答：**

C 程序从源代码到可执行文件通常经过预处理、编译、汇编和链接四个阶段。预处理处理宏定义、头文件包含、条件编译和注释删除；编译把预处理后的源程序翻译成汇编代码；汇编把汇编代码转换为目标文件；链接把多个目标文件和库文件合并，生成可执行程序。


## 问题 10：编译和解释有什么区别？

**答：**

编译是先把整个源程序翻译成目标程序，再运行目标程序；解释是边翻译边执行，不生成独立的目标程序。编译方式通常运行速度快，但移植性相对较差；解释方式启动灵活、跨平台性较好，但运行时通常需要解释器，执行效率相对较低。
