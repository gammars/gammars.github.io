# Data Structures and Algorithms: English Interview Defense Guide

> This is an English speaking guide for graduate-school interviews. The answers are deliberately concise: first give the definition, then explain the mechanism, complexity, and trade-off. If the interviewer asks for more detail, continue with the follow-up points.

## How to Answer an Algorithm Question

### A reliable 30-second structure

1. **Definition:** “A ___ is a data structure/algorithm that ...”
2. **Core idea:** “The key idea is to ...”
3. **Complexity:** “Its time complexity is ... and its space complexity is ...”
4. **Condition or trade-off:** “It works well when ..., but the limitation is ...”
5. **Example:** “A typical application is ...”

### Useful opening sentences

- “Let me explain it from the definition, the operation, and the complexity.”
- “The most important invariant is ...”
- “This complexity assumes that ...”
- “The average-case and worst-case complexities are different here.”
- “The answer depends on whether the position is already known.”
- “Compared with ___, it sacrifices ___ in exchange for ___.”
- “The algorithm is correct because each step preserves the following invariant: ...”

## 1. Foundations and Linear Structures

### 1.1 What is a data structure?

**Answer:**

> A data structure is a way of organizing and storing data so that operations such as access, search, insertion, deletion, and update can be performed efficiently. It has both a logical structure, which describes the relationships among data elements, and a physical representation, which describes how the data is stored in memory.

**Follow-up points:**

- An array and a linked list can represent the same logical linear list.
- Different structures make different trade-offs between time, space, and flexibility.
- An abstract data type specifies what operations mean, while a data structure specifies how they are implemented.

### 1.2 What is an abstract data type?

**Answer:**

> An abstract data type, or ADT, is a mathematical model defined by its values and supported operations, without specifying the implementation. For example, a stack ADT supports `push`, `pop`, and `top`, and follows the last-in-first-out rule. It can be implemented by either an array or a linked list.

### 1.3 What is a linear data structure?

**Answer:**

> A linear data structure stores elements in a sequential relationship. Except for the first and the last element, each element usually has one predecessor and one successor. Arrays, linked lists, stacks, queues, and deques are common examples.

### 1.4 Compare an array with a linked list.

**Answer:**

> An array stores elements in contiguous memory, so it supports constant-time random access by index, namely $O(1)$. However, inserting or deleting an element in the middle usually requires shifting elements, so the cost is $O(n)$. A linked list stores nodes connected by pointers. It does not support constant-time random access, because we must follow links from the head. Its access and search cost is usually $O(n)$, but insertion or deletion can be $O(1)$ when the target position or the predecessor node is already known.

**Key trap:**

> Saying “linked-list insertion is always $O(1)$” is incomplete. Finding the position may take $O(n)$; only changing the links after the position is known takes $O(1)$.

### 1.5 Why can an array access an element in $O(1)$?

**Answer:**

> Because array elements have a fixed size and are stored contiguously. If the base address is $base$, the element size is $L$, and the index is $i$, the address can be calculated directly as $base+iL$, up to the language’s indexing convention. No previous elements need to be visited.

### 1.6 What is a linked list?

**Answer:**

> A linked list is a collection of nodes. Each node stores data and one or more links to other nodes. The nodes do not need to be contiguous in memory. A singly linked list stores a pointer to the next node, while a doubly linked list stores both previous and next pointers.

### 1.7 What are the advantages of a dummy head node?

**Answer:**

> A dummy head node is an extra node placed before the first real node. It makes the head a normal predecessor, so insertion and deletion at the beginning use the same logic as operations in the middle. This reduces special cases and makes pointer manipulation safer.

### 1.8 Compare singly and doubly linked lists.

**Answer:**

> A singly linked list uses less memory because each node stores only a next pointer, but it can move only forward and deleting a node often requires its predecessor. A doubly linked list stores both previous and next pointers, so it supports movement in both directions and can delete a known node more conveniently. The trade-off is extra memory and more pointer updates.

### 1.9 What is a stack?

**Answer:**

> A stack is a last-in-first-out, or LIFO, data structure. Its main operations are `push`, `pop`, and `top` or `peek`. If implemented appropriately, these operations take $O(1)$ time. Stacks are used in function calls, recursion, expression evaluation, syntax checking, and depth-first search.

### 1.10 What is a queue?

**Answer:**

> A queue is a first-in-first-out, or FIFO, data structure. Elements are inserted at the rear and removed from the front. With both front and rear pointers, enqueue and dequeue can be implemented in $O(1)$ time. Queues are used in scheduling, buffering, breadth-first search, and level-order traversal.

### 1.11 Why does a circular queue need a circular representation?

**Answer:**

> In a normal array queue, repeatedly removing elements from the front can leave unused space at the beginning. A circular queue treats the array as a ring and moves the front and rear indices using modulo arithmetic. This reuses freed positions without shifting all elements.

### 1.12 How do you distinguish an empty circular queue from a full one?

**Answer:**

> The exact rule depends on the implementation. One common method reserves one slot: the queue is empty when `front == rear`, and full when `(rear + 1) % capacity == front`. Another method stores an explicit size or count. The important point is to define the invariant before writing the conditions.

### 1.13 What is a deque?

**Answer:**

> A deque, or double-ended queue, allows insertion and deletion at both the front and the rear. It can behave like both a stack and a queue. A circular array or a doubly linked list is a common implementation.

## 2. Recursion, Divide and Conquer, and Binary Search

### 2.1 What is recursion?

**Answer:**

> Recursion is a technique in which a function solves a problem by calling itself on a smaller instance of the same problem. A correct recursive solution needs a base case that stops the recursion and a recursive case that makes progress toward the base case.

### 2.2 What happens during a recursive call?

**Answer:**

> Each call creates a stack frame containing parameters, local variables, and a return address. The frames accumulate until a base case is reached, and then they are removed in reverse order. Therefore, recursion depth usually determines the auxiliary stack space.

### 2.3 Is recursion always slower than iteration?

**Answer:**

> Not always. Recursion can make tree traversal and divide-and-conquer algorithms clearer, but function-call overhead and call-stack space may be additional costs. An iterative version may use less overhead. The actual time complexity depends on the number of calls and the work done in each call, not just on whether the code is recursive.

### 2.4 What is divide and conquer?

**Answer:**

> Divide and conquer solves a problem in three stages: divide the input into smaller subproblems, conquer those subproblems recursively, and combine their solutions. Merge sort is a typical example. Its recurrence is $T(n)=2T(n/2)+O(n)$, which gives $O(n\log n)$ time.

### 2.5 Is every recursive algorithm a divide-and-conquer algorithm?

**Answer:**

> No. Recursion is an implementation or problem-solving technique, while divide and conquer is a particular algorithmic strategy. A recursive factorial function is recursive but does not divide a problem into independent subproblems. Conversely, divide and conquer is often implemented recursively, but the concepts are not identical.

### 2.6 What is binary search?

**Answer:**

> Binary search finds a target in a sorted or monotonic search space. It compares the target with the middle element and discards the half that cannot contain the answer. The search range is approximately halved at every step, so the time complexity is $O(\log n)$ and the iterative auxiliary space is $O(1)$.

### 2.7 What condition is necessary for binary search?

**Answer:**

> Binary search needs a property that allows us to safely eliminate a part of the search space. A sorted array is the standard example. More generally, the predicate or answer condition must be monotonic; otherwise, discarding half of the candidates may discard the correct answer.

### 2.8 Why is `left + (right - left) / 2` safer than `(left + right) / 2`?

**Answer:**

> If `left` and `right` are large, their sum may overflow the integer range. The expression `left + (right - left) / 2` computes the same midpoint while avoiding that addition overflow, assuming the subtraction itself is safe.

### 2.9 What is the difference between a closed and a half-open binary-search interval?

**Answer:**

> A closed interval uses `[left, right]`, so the loop usually continues while `left <= right`, and the updates exclude `mid` with `right = mid - 1` or `left = mid + 1`. A half-open interval uses `[left, right)`, so the loop condition and updates are different. Both are correct if the invariant is consistent; mixing the two conventions causes off-by-one errors.

## 3. Strings, Pattern Matching, and Sparse Data

### 3.1 What is a string?

**Answer:**

> A string is a finite sequence of characters. It can be stored in a fixed-length array, a dynamically allocated array, or a linked block structure. The representation affects memory usage, resizing cost, random access, and concatenation performance.

### 3.2 What is substring or pattern matching?

**Answer:**

> Pattern matching asks whether a pattern $P$ of length $m$ occurs in a text $T$ of length $n$, and often asks for its starting position. The brute-force method may take $O(nm)$ time in the worst case because it can repeat comparisons after a mismatch.

### 3.3 How would you introduce KMP in English?

**Answer:**

> KMP, or Knuth–Morris–Pratt, is a pattern-matching algorithm that avoids rechecking characters after a mismatch. It preprocesses the pattern and builds an LPS, or longest proper prefix which is also a suffix, array. When a mismatch occurs, the pattern index jumps according to the LPS value while the text index does not move backward. The preprocessing takes $O(m)$, the matching takes $O(n)$, and the total time is $O(n+m)$.

### 3.4 What does `lps[i]` mean?

**Answer:**

> `lps[i]` is the length of the longest proper prefix of `pattern[0..i]` that is also a suffix of `pattern[0..i]`. “Proper” means that the prefix cannot be the entire substring. It tells KMP how far the pattern can fall back without losing information already obtained.

### 3.5 Why is KMP not $O(nm)$ even though the pattern index may fall back?

**Answer:**

> The pattern index can fall back, but the text index never moves backward. Each forward move or fallback is charged to a limited number of index movements, so the total work is linear in the text and pattern lengths. Therefore the total complexity remains $O(n+m)$, not $O(nm)$.

### 3.6 What is a sparse matrix?

**Answer:**

> A sparse matrix contains mostly zero or default values. Storing every position wastes memory, so we store only nonzero entries, usually as triples containing the row, column, and value. Sparse representations save space when the number of nonzero elements is much smaller than the total number of positions, but they may make random access more complicated.

## 4. Trees and Tree-Based Structures

### 4.1 What is a tree?

**Answer:**

> A tree is a connected acyclic graph. Equivalently, it is a hierarchical structure with one root, and every node except the root has exactly one parent. If a tree has $n$ nodes, it has $n-1$ edges. Trees are useful for representing hierarchy and supporting recursive search.

### 4.2 Explain common tree terminology.

**Answer:**

> The root is the top node. A parent is directly connected to a child. A node with no children is a leaf. The degree of a node is its number of children, while the degree of a tree is the maximum node degree. The depth of a node is its distance from the root, and the height of a tree is the maximum depth of any node. Some textbooks count edges and others count levels, so the convention should be stated clearly.

### 4.3 What is a binary tree?

**Answer:**

> A binary tree is a tree in which each node has at most two children, usually called the left child and the right child. The two positions are distinct even when only one child exists. A binary tree is not necessarily a binary search tree; the latter has an additional ordering property.

### 4.4 What are preorder, inorder, and postorder traversal?

**Answer:**

> In preorder traversal, we visit the root before the left and right subtrees: root-left-right. In inorder traversal, we visit left-root-right. In postorder traversal, we visit left-right-root. Each traversal visits every node once, so its time complexity is $O(n)$, and the recursive auxiliary space is $O(h)$, where $h$ is the tree height.

### 4.5 Why does inorder traversal of a binary search tree produce sorted order?

**Answer:**

> A binary search tree maintains the invariant that every key in the left subtree is smaller than the node’s key and every key in the right subtree is larger, subject to the duplicate-key policy. Inorder traversal visits the left subtree, then the node, then the right subtree, so it outputs keys in nondecreasing or strictly increasing order depending on that policy.

### 4.6 How would you introduce a binary search tree?

**Answer:**

> A binary search tree, or BST, is a binary tree whose keys satisfy the ordering invariant: keys in the left subtree are smaller than the node’s key, and keys in the right subtree are larger. Search, insertion, and deletion take $O(h)$, where $h$ is the tree height. They are $O(\log n)$ when the tree is balanced, but can degrade to $O(n)$ when the tree becomes a chain.

### 4.7 How does BST search work?

**Answer:**

> Starting at the root, compare the target with the current key. If they are equal, return the node. If the target is smaller, move to the left child; otherwise move to the right child. The search follows one root-to-leaf path, so the time complexity is $O(h)$ and the iterative space is $O(1)$.

### 4.8 How do you delete a node from a BST?

**Answer:**

> There are three cases. If the node is a leaf, remove it directly. If it has one child, connect its parent to that child. If it has two children, replace its key with the inorder successor or predecessor, and then delete that successor or predecessor, which has at most one child. The operation takes $O(h)$.

### 4.9 Why can a BST become inefficient?

**Answer:**

> If keys are inserted in an already sorted or nearly sorted order, each new node may become the only child of the previous node. The height then approaches $n-1$, so search, insertion, and deletion degrade from $O(\log n)$ to $O(n)$. Randomized insertion or self-balancing trees can reduce this problem.

### 4.10 What is an AVL tree?

**Answer:**

> An AVL tree is a self-balancing binary search tree. For every node, the height difference between its left and right subtrees, called the balance factor, is at most one in absolute value. After insertion or deletion, rotations restore the balance. The height remains $O(\log n)$, so search, insertion, and deletion are all $O(\log n)$.

### 4.11 Why do rotations preserve the BST property?

**Answer:**

> A rotation changes the local parent-child relationships but preserves the inorder sequence of the involved nodes. Since inorder order is exactly the sorted-key order of a BST, the ordering invariant remains true. The rotation changes the height structure without changing the relative order of keys.

### 4.12 What are LL, RR, LR, and RL cases?

**Answer:**

> LL and RR are single-rotation cases: LL is fixed by a right rotation, and RR by a left rotation. LR and RL are double-rotation cases: LR uses a left rotation on the child followed by a right rotation on the unbalanced node, while RL is symmetric. The names describe the direction of the imbalance path.

### 4.13 What is a heap?

**Answer:**

> A heap is a complete binary tree that satisfies a heap-order property. In a max-heap, every parent is at least as large as its children; in a min-heap, every parent is at most as large as its children. A heap is commonly stored in an array, where the children of node $i$ are at indices $2i$ and $2i+1$ under one-based indexing. Getting the root is $O(1)$, and inserting or deleting the root is $O(\log n)$.

### 4.14 Why is bottom-up heap construction $O(n)$, not $O(n\log n)$?

**Answer:**

> The simple upper bound of $n$ nodes times $O(\log n)$ is loose. Most nodes are near the leaves and can move only a small distance during heapify. Summing the work over all heights gives a convergent series multiplied by $n$, so bottom-up construction is $O(n)$. Repeatedly inserting $n$ elements would instead cost $O(n\log n)$.

### 4.15 What is a threaded binary tree?

**Answer:**

> A threaded binary tree uses otherwise-null child pointers to store links to a node’s traversal predecessor or successor, often in inorder. These threads allow traversal with less auxiliary stack space, but the implementation needs extra tag bits or metadata to distinguish a real child link from a thread.

### 4.16 What is a B-tree?

**Answer:**

> A B-tree is a balanced multiway search tree designed to reduce the number of external-memory accesses. A node can contain many keys and many children, so the height is small. All leaves are at the same level, and insertion and deletion maintain balance through splitting, borrowing, or merging nodes.

### 4.17 Compare a B-tree with a B+ tree.

**Answer:**

> In a B+ tree, internal nodes mainly store separator keys, while actual records are stored in the leaves. The leaves are usually linked in sorted order. This makes range queries and sequential scans efficient. A B-tree may store records in internal nodes as well, so a successful search can finish earlier, but range traversal is often less convenient. Both are balanced multiway trees designed for external storage.

### 4.18 What is a trie?

**Answer:**

> A trie is a prefix tree for strings. Each edge represents a character, and a path from the root represents a prefix or a complete word. Searching, inserting, and prefix querying take $O(L)$, where $L$ is the string length, independent of the number of stored words, assuming character transitions are efficient. The trade-off is potentially high memory usage.

### 4.19 What is a Fenwick tree?

**Answer:**

> A Fenwick tree, or binary indexed tree, stores partial prefix sums in an array. The least significant set bit of an index determines the covered range. A prefix query and a point update both take $O(\log n)$, and a range sum can be obtained from two prefix queries. It uses $O(n)$ space and is especially suitable for invertible operations such as sums.

### 4.20 What is a segment tree?

**Answer:**

> A segment tree recursively partitions an array into intervals. Each node stores an aggregate value for its interval, such as a sum, minimum, or maximum. A range query and a point update usually take $O(\log n)$, while a lazy-propagation version can support some range updates in $O(\log n)$. It is more flexible than a Fenwick tree but uses more memory and is more complicated.

## 5. Graphs and Graph Algorithms

### 5.1 How would you introduce a graph?

**Answer:**

> A graph consists of a set of vertices and a set of edges connecting pairs of vertices. It may be directed or undirected, weighted or unweighted. Graphs model networks such as roads, communication links, dependencies, and social relationships.

### 5.2 What are degree, indegree, and outdegree?

**Answer:**

> In an undirected graph, the degree of a vertex is the number of incident edges. In a directed graph, indegree is the number of incoming edges and outdegree is the number of outgoing edges. In an undirected graph, the sum of all degrees equals $2|E|$; in a directed graph, the sum of indegrees and the sum of outdegrees both equal $|E|$.

### 5.3 Compare an adjacency matrix with an adjacency list.

**Answer:**

> An adjacency matrix uses a $V\times V$ table. It uses $O(V^2)$ space and tests whether two vertices are directly connected in $O(1)$, so it is suitable for dense graphs. An adjacency list stores only existing edges and uses $O(V+E)$ space. It is usually better for sparse graphs and makes neighbor traversal efficient.

### 5.4 How would you introduce DFS?

**Answer:**

> DFS, or depth-first search, explores one path as deeply as possible before backtracking. It can be implemented recursively or with an explicit stack. We mark a vertex when it is first visited, then recursively explore its unvisited neighbors. With an adjacency list, the time complexity is $O(V+E)$, and the auxiliary space is $O(V)$. DFS is used for connectivity, cycle detection, topological sorting, components, and backtracking.

### 5.5 How would you introduce BFS?

**Answer:**

> BFS, or breadth-first search, explores vertices level by level. It uses a queue: enqueue the start vertex, repeatedly dequeue a vertex, and enqueue each unvisited neighbor. With an adjacency list, its time complexity is $O(V+E)$. In an unweighted graph, the first time BFS visits a vertex, it has found a shortest path in terms of the number of edges.

### 5.6 Compare DFS and BFS.

**Answer:**

> DFS goes deep along one branch before returning, while BFS expands one layer at a time. DFS naturally uses a stack or recursion and is good for cycle detection, topological ordering, and exhaustive search. BFS uses a queue and is good for shortest paths in unweighted graphs and level-order problems. With the same adjacency-list representation, both take $O(V+E)$ time.

### 5.7 How can DFS detect a cycle?

**Answer:**

> In an undirected graph, during DFS, an edge to an already visited vertex indicates a cycle if that vertex is not the current node’s parent. In a directed graph, we use three states: unvisited, currently in the recursion stack, and fully processed. An edge to a currently active vertex is a back edge and proves a directed cycle.

### 5.8 What is a topological order?

**Answer:**

> A topological order is a linear ordering of the vertices of a directed acyclic graph such that every directed edge $u\to v$ places $u$ before $v$. Kahn’s algorithm repeatedly removes zero-indegree vertices using a queue. DFS can also produce an order by pushing a vertex after all its descendants are processed. A topological order exists if and only if the graph is acyclic.

### 5.9 What is a minimum spanning tree?

**Answer:**

> A minimum spanning tree, or MST, is a spanning tree of a connected, weighted, undirected graph with minimum total edge weight. It contains all vertices and exactly $V-1$ edges, with no cycle. Prim’s and Kruskal’s algorithms are common solutions.

### 5.10 Compare Prim’s and Kruskal’s algorithms.

**Answer:**

> Prim’s algorithm grows one tree from a chosen start vertex. At each step it adds the minimum-weight edge connecting the current tree to an outside vertex. Kruskal’s algorithm sorts all edges by weight and adds an edge if it does not create a cycle, usually using a disjoint-set union structure. Both are greedy algorithms. With appropriate implementations, their typical complexity is $O(E\log V)$ or $O(E\log E)$.

### 5.11 Why is Kruskal’s algorithm safe?

**Answer:**

> The cut property says that a minimum-weight edge crossing a cut is safe to include in some MST. Kruskal considers edges in nondecreasing order and adds an edge only when it connects two different components. Therefore the edge is the lightest available edge across the corresponding cut and does not create a cycle.

### 5.12 How would you introduce Dijkstra’s algorithm?

**Answer:**

> Dijkstra’s algorithm finds single-source shortest paths when all edge weights are nonnegative. It repeatedly selects the unvisited vertex with the smallest tentative distance, finalizes it, and relaxes its outgoing edges. With a binary heap and adjacency lists, the complexity is typically $O((V+E)\log V)$. It is not correct for graphs with negative-weight edges because a finalized distance may later be improved.

### 5.13 What does edge relaxation mean?

**Answer:**

> To relax an edge $u\to v$, we check whether going through $u$ gives a shorter path to $v$. If `dist[v] > dist[u] + weight(u,v)`, we update `dist[v]` and record $u$ as the predecessor. Relaxation is the central operation in shortest-path algorithms.

### 5.14 How would you introduce Floyd–Warshall?

**Answer:**

> Floyd–Warshall is a dynamic-programming algorithm for all-pairs shortest paths. It gradually allows vertices $1,2,\ldots,k$ to be used as intermediate vertices. The recurrence is $D_k(i,j)=\min(D_{k-1}(i,j),D_{k-1}(i,k)+D_{k-1}(k,j))$. Its time complexity is $O(V^3)$ and its standard space complexity is $O(V^2)$. It can handle negative edges but not a negative cycle if shortest paths are required.

### 5.15 What is a negative cycle?

**Answer:**

> A negative cycle is a cycle whose total weight is negative. If it is reachable from the source, the path cost can be reduced without bound by traversing the cycle repeatedly, so a finite shortest path does not exist. In Floyd–Warshall, a negative diagonal entry after processing indicates a negative cycle.

### 5.16 What is a flow network?

**Answer:**

> A flow network is a directed graph with capacities on edges, a source, and a sink. A flow must respect capacity constraints and flow conservation at intermediate vertices. The maximum-flow problem asks for the greatest amount that can be sent from the source to the sink. The max-flow min-cut theorem states that the maximum flow value equals the capacity of a minimum cut.

## 6. Searching and Hashing

### 6.1 Compare sequential search and binary search.

**Answer:**

> Sequential search checks elements one by one and does not require sorted data. Its worst-case time is $O(n)$. Binary search requires a sorted or monotonic search space, but it reduces the range by half each time and takes $O(\log n)$. Sequential search is simpler and can be better for very small or rarely queried data.

### 6.2 What is ASL?

**Answer:**

> ASL means average search length. It is the expected number of comparisons needed to complete a search, usually weighted by the probability of each successful or unsuccessful outcome. For a uniformly successful sequential search in an array of $n$ elements, the average number of comparisons is $$n+1$/2$. The exact value depends on the probability model.

### 6.3 What is a hash table?

**Answer:**

> A hash table stores key-value pairs by mapping a key to an array index through a hash function. Under a reasonably uniform distribution and a controlled load factor, insertion, deletion, and lookup are expected to take $O(1)$ time. The worst case can still be $O(n)$ if many keys collide.

### 6.4 What is a collision, and how can it be handled?

**Answer:**

> A collision occurs when different keys map to the same table position. Separate chaining stores a collection, such as a linked list or dynamic array, at each position. Open addressing stores all entries in the table and probes alternative positions, using strategies such as linear probing, quadratic probing, or double hashing. Each method has different cache behavior and deletion rules.

### 6.5 What is the load factor?

**Answer:**

> The load factor is usually defined as $\alpha=n/m$, where $n$ is the number of stored entries and $m$ is the table capacity. As $\alpha$ grows, collisions and probe lengths generally increase. A hash table may resize and rehash its entries when the load factor passes a threshold. Therefore average $O(1)$ performance depends on both the hash function and load-factor management.

### 6.6 Why can a hash table still be slow if lookup is theoretically $O(1)$?

**Answer:**

> $O(1)$ is an expected or average-case statement under assumptions; it is not a guarantee that every lookup takes exactly one operation. Poor hash distribution, a high load factor, many collisions, resizing, cache effects, and an expensive hash function can all increase the actual cost. In the worst case, lookup can degrade to $O(n)$.

### 6.7 Compare a hash table with a BST.

**Answer:**

> A hash table offers expected $O(1)$ equality lookup but does not naturally maintain sorted order or support efficient range queries. A balanced BST offers $O(\log n)$ worst-case search and maintains order, so predecessor, successor, and range operations are natural. The choice depends on whether the application needs fast equality lookup or ordered operations.

## 7. Sorting Algorithms

### 7.1 What is sorting stability?

**Answer:**

> A sorting algorithm is stable if equal-key elements keep their original relative order after sorting. Stability matters when records have multiple fields and we sort by one field after previously sorting by another. It is a property of a particular implementation, not just the algorithm’s name.

### 7.2 What is an in-place sorting algorithm?

**Answer:**

> An in-place algorithm uses only $O(1)$ or a small amount of extra storage, excluding the input array. The exact definition varies, especially for recursion stacks. For example, heap sort is usually considered in-place, while standard array merge sort needs $O(n)$ auxiliary storage.

### 7.3 Why is the comparison-sorting lower bound $\Omega(n\log n)$?

**Answer:**

> For $n$ distinct elements, there are $n!$ possible input permutations. A comparison algorithm can be represented by a binary decision tree, where each comparison has two outcomes. The tree must have at least $n!$ leaves, so its height is at least $\log_2(n!)=\Omega(n\log n)$. This lower bound applies to general comparison-based sorting, not to algorithms that exploit extra information about the keys.

### 7.4 How would you introduce insertion sort?

**Answer:**

> Insertion sort maintains a sorted prefix. It takes the next element from the unsorted part and shifts larger elements to insert it into the correct position. It is stable and in-place. Its best-case time is $O(n)$ for nearly sorted data, while its average and worst-case time is $O(n^2)$.

### 7.5 How would you introduce selection sort?

**Answer:**

> Selection sort repeatedly scans the unsorted part, selects the smallest element, and swaps it into the next position. It is simple and in-place, but it performs $O(n^2)$ comparisons regardless of whether the input is already sorted. The standard swap-based implementation is not stable.

### 7.6 How would you introduce bubble sort?

**Answer:**

> Bubble sort repeatedly compares adjacent elements and swaps them when they are out of order. Large elements gradually move to the end. A version with an early-exit flag has best-case $O(n)$ time on sorted data, but the average and worst cases are $O(n^2)$. It is usually stable but rarely preferred for large inputs.

### 7.7 How would you introduce shell sort?

**Answer:**

> Shell sort is a generalized insertion sort. It first performs insertion sort on elements separated by a gap, then decreases the gap until it becomes one. The performance depends strongly on the gap sequence, so unlike insertion, selection, or merge sort, there is no single simple complexity statement independent of the chosen sequence. It is usually in-place and generally not stable.

### 7.8 How would you introduce merge sort?

**Answer:**

> Merge sort divides the array into two halves, recursively sorts both halves, and merges the two sorted sequences. Its time complexity is $O(n\log n)$ in the best, average, and worst cases. It is stable when the merge step chooses the left element first on equal keys. The standard array implementation needs $O(n)$ auxiliary space.

### 7.9 How would you introduce quicksort?

**Answer:**

> Quicksort chooses a pivot and partitions the array so that elements on one side are no greater than the pivot and elements on the other side are no smaller. It recursively sorts the two subarrays. Balanced partitions give average $O(n\log n)$ time, while repeatedly choosing the smallest or largest pivot gives worst-case $O(n^2)$. It is often fast in practice and can use little extra array space, but the standard version is not stable.

### 7.10 Why can quicksort degrade to $O(n^2)$?

**Answer:**

> If every partition produces subarrays of sizes zero and $n-1$, the recurrence becomes $T(n)=T(n-1)+O(n)$, which sums to $O(n^2)$. This can happen when the pivot is consistently the smallest or largest element, for example when a fixed first element is chosen on already sorted input.

### 7.11 What does randomized quicksort change?

**Answer:**

> Randomly choosing the pivot or shuffling the input makes consistently bad partitions unlikely. It improves expected performance, which is $O(n\log n)$, but it does not remove the theoretical worst case of $O(n^2)$. Randomization changes the probability distribution of inputs or pivots, not the worst-case bound.

### 7.12 How would you introduce heap sort?

**Answer:**

> Heap sort first builds a heap and then repeatedly removes the maximum or minimum element, placing it at the end of the array. Bottom-up heap construction takes $O(n)$, and each of $n$ removals takes $O(\log n)$, so the total time is $O(n\log n)$. It is in-place, has a predictable worst-case bound, and is usually not stable.

### 7.13 How would you introduce counting sort?

**Answer:**

> Counting sort does not compare elements. It counts the occurrences of each integer in a known value range and reconstructs the output from those counts. Its time and space depend on both the number of elements $n$ and the value range $k$, often written $O(n+k)$. It can beat the comparison lower bound when the key range is small enough, but it is unsuitable when the range is huge.

### 7.14 How would you introduce radix sort?

**Answer:**

> Radix sort processes keys digit by digit, usually from the least significant digit to the most significant digit. Each pass uses a stable intermediate sort, commonly counting sort. If there are $d$ digits and the digit range is $r$, a typical bound is $O(d(n+r))$. It is useful for fixed-format integers or strings, but requires assumptions about the key representation.

### 7.15 What is bucket sort?

**Answer:**

> Bucket sort distributes elements into intervals called buckets, sorts each bucket, and concatenates the results. Its average performance can be close to $O(n)$ when the input is distributed approximately uniformly and the buckets are balanced. In an unfavorable distribution, one bucket may contain almost all elements, so the worst case can be $O(n^2)$ depending on the inner sort.

### 7.16 Compare merge sort, quicksort, and heap sort.

**Answer:**

> Merge sort has stable $O(n\log n)$ time but usually needs $O(n)$ auxiliary space for arrays. Quicksort has average $O(n\log n)$ time and is often fast in practice, but its worst case is $O(n^2)$. Heap sort has $O(n\log n)$ worst-case time and $O(1)$ auxiliary array space, but it is not stable and may have poorer cache behavior.

### 7.17 How do you choose a sorting algorithm?

**Answer:**

> I would consider the input size, whether the data is nearly sorted, whether stability is required, whether extra memory is available, whether the keys have special structure, and whether a worst-case guarantee is important. For example, insertion sort suits small or nearly sorted data, merge sort suits stable predictable sorting, quicksort is often a strong general-purpose choice, and counting or radix sort is attractive when the key domain is restricted.

## 8. Dynamic Programming and Greedy Algorithms

### 8.1 How would you introduce dynamic programming?

**Answer:**

> Dynamic programming solves a problem by defining states, expressing transitions between states, and storing solutions to overlapping subproblems. It applies when the problem has optimal substructure and overlapping subproblems. It can be implemented top-down with memoization or bottom-up with tabulation.

### 8.2 What is a DP state?

**Answer:**

> A DP state is a compact description of the information needed to determine the remaining subproblem. For example, in a 0/1 knapsack problem, `dp[i][c]` can represent the maximum value obtained using the first $i$ items with capacity $c$. A good state contains enough information for a correct transition but no unnecessary information.

### 8.3 What are overlapping subproblems and optimal substructure?

**Answer:**

> Overlapping subproblems means the same smaller problems appear repeatedly, so caching their answers avoids recomputation. Optimal substructure means an optimal solution can be composed from optimal solutions to relevant subproblems. Both properties are important for standard dynamic programming, although their exact formulations depend on the problem.

### 8.4 Compare memoization with bottom-up DP.

**Answer:**

> Memoization is top-down: it follows the recursive dependency graph and computes a state only when needed. Bottom-up DP is iterative: it computes states in an order that guarantees all dependencies are ready. Memoization can be easier to write and may skip unreachable states, while bottom-up DP often has lower call overhead and makes memory optimization easier.

### 8.5 How would you introduce the 0/1 knapsack problem?

**Answer:**

> In the 0/1 knapsack problem, each item can be selected at most once. If `dp[i][c]` is the best value using the first $i$ items with capacity $c$, the transition is the maximum of not taking item $i$ and taking it when it fits. The standard time complexity is $O(nC)$, where $C$ is the capacity, and the one-dimensional optimization uses $O(C)$ space.

### 8.6 Why must a one-dimensional 0/1 knapsack array be updated backward?

**Answer:**

> Updating capacity from large to small ensures that the current item is not reused in the same iteration. When we process capacity $c$, the value at $c-w_i$ still represents the previous item layer. Updating forward would allow the value just updated for item $i$ to be used again, which changes the problem into an unbounded-knapsack variant.

### 8.7 What is the difference between DP and divide and conquer?

**Answer:**

> Divide and conquer usually solves independent subproblems and combines their results. Dynamic programming is used when subproblems overlap, so it stores and reuses their solutions. Both may use recurrences, but the presence of overlapping subproblems and a useful state representation is the key distinction.

### 8.8 How would you introduce a greedy algorithm?

**Answer:**

> A greedy algorithm makes the best-looking local choice at each step and never revises that choice. It is correct only when the problem has a greedy-choice property and an appropriate proof, often using an exchange argument or a cut property. Greedy algorithms are usually simple and efficient, but a locally optimal choice is not automatically globally optimal.

### 8.9 Why does greedy activity selection work?

**Answer:**

> For the unweighted activity-selection problem, selecting the compatible activity with the earliest finishing time leaves the largest possible remaining time. By an exchange argument, there exists an optimal solution whose first activity is this earliest-finishing activity. We can therefore make the greedy choice and solve the remaining suffix recursively.

### 8.10 Compare greedy algorithms with dynamic programming.

**Answer:**

> Greedy algorithms commit to local choices and usually use less memory and less computation, but they need a greedy-choice proof. Dynamic programming considers a structured set of states and keeps enough alternatives to guarantee an optimum under its assumptions. Greedy is often faster when applicable; DP is more general for many overlapping-subproblem problems.

## 9. Backtracking and Branch and Bound

### 9.1 How would you introduce backtracking?

**Answer:**

> Backtracking explores a solution space depth first. It makes a tentative choice, checks whether the partial solution can still lead to a valid answer, recursively continues if possible, and then undoes the choice before trying another branch. Its essential pattern is “choose, explore, and undo.”

### 9.2 What is a solution-space tree?

**Answer:**

> A solution-space tree represents partial decisions as nodes and possible next decisions as children. A root-to-leaf path represents a complete assignment. A subset tree usually has two choices per element, while a permutation tree has a choice among the remaining elements. The representation determines the search size and the available pruning conditions.

### 9.3 What are explicit and implicit constraints?

**Answer:**

> An explicit constraint defines the possible values of a decision variable, such as choosing a position from a fixed range. An implicit constraint describes relationships that must hold among decisions, such as “no two queens attack each other.” Backtracking uses both types to decide whether a partial assignment is feasible.

### 9.4 What is pruning?

**Answer:**

> Pruning means stopping the exploration of a branch as soon as we know that it cannot produce a valid or better solution. Feasibility pruning rejects a partial solution that violates a constraint. Optimality pruning rejects a branch whose best possible bound is no better than the current best answer. Good pruning can reduce practical running time dramatically, but the worst case may still be exponential.

### 9.5 Why is backtracking often implemented with DFS?

**Answer:**

> A depth-first traversal naturally maintains one current decision path. When a branch is finished, the algorithm can undo the last choice and reuse the same memory for the next branch. This gives backtracking a simple implementation and usually requires space proportional to the maximum depth, apart from the representation of the current state.

### 9.6 What is branch and bound?

**Answer:**

> Branch and bound also explores a solution-space tree, but it is mainly used for optimization problems. It branches into subproblems and computes a bound on the best result that each subproblem could possibly achieve. If that bound cannot beat the current best solution, the subproblem is discarded. A priority queue can expand the most promising live node first.

### 9.7 Compare backtracking with branch and bound.

**Answer:**

> Backtracking usually emphasizes feasibility and explores choices in a depth-first manner, pruning invalid partial solutions. Branch and bound emphasizes optimization and prunes subproblems using objective bounds; it may use breadth-first, best-first, or priority-queue search. Both systematically explore a solution space, and both depend heavily on effective pruning.

### 9.8 Why can subset search be exponential?

**Answer:**

> If each of $n$ elements can be either selected or not selected, there are $2^n$ complete subsets. Even if each node is processed in constant time, the search tree has exponential size. Pruning may improve typical performance but cannot generally change the worst-case exponential bound for arbitrary instances.

## 10. Cross-Topic Follow-Up Questions

### 10.1 What is an invariant, and why is it useful?

**Answer:**

> An invariant is a property that remains true before and after each iteration or recursive step. It connects the implementation with the correctness proof. For binary search, an invariant may be that the answer, if it exists, is still inside the current interval. For a heap, it is the heap-order property. If initialization, maintenance, and termination are all justified, the algorithm is easier to prove correct.

### 10.2 How do you prove an algorithm correct?

**Answer:**

> I first state the invariant or induction hypothesis. Then I prove that it is true initially, remains true after every operation, and implies the desired result when the algorithm terminates. For recursive algorithms, I also prove that each recursive call is made on a smaller instance and that the base case is correct.

### 10.3 What is the difference between worst-case and average-case complexity?

**Answer:**

> Worst-case complexity bounds the maximum cost over all inputs of a given size. Average-case complexity is the expected cost under a specified probability distribution over inputs or random choices. An average-case statement is meaningful only when the distribution or randomization assumptions are clear. It does not replace a worst-case guarantee.

### 10.4 What is amortized analysis?

**Answer:**

> Amortized analysis studies the average cost per operation over a sequence of operations, without assuming a probability distribution. Some individual operations may be expensive, but the total cost of a long sequence can be bounded. Dynamic-array expansion is a standard example: a resize may cost $O(n)$, but the amortized append cost is $O(1)$ when the capacity grows geometrically.

### 10.5 What is the difference between time complexity and actual running time?

**Answer:**

> Time complexity describes how the cost grows as the input size increases and usually ignores constants and lower-order terms. Actual running time also depends on implementation constants, hardware, memory hierarchy, language overhead, input distribution, and cache behavior. Complexity is essential for scalability, but it is not a complete performance measurement for small inputs.

### 10.6 When should you use a stack, a queue, or a priority queue?

**Answer:**

> I use a stack when the most recent item should be processed first, such as DFS or undo operations. I use a queue when items should be processed in arrival or level order, such as BFS. I use a priority queue when the next item should be chosen by a key, such as the smallest tentative distance in Dijkstra’s algorithm.

### 10.7 Why is representation important in graph algorithms?

**Answer:**

> The graph representation determines both memory use and the cost of primitive operations. An adjacency matrix gives $O(1)$ edge existence tests but costs $O(V^2)$ space. An adjacency list uses $O(V+E)$ space and is usually better for sparse graphs because algorithms can iterate over actual neighbors instead of scanning all possible vertices.

### 10.8 What does “trade-off” mean in data structures?

**Answer:**

> A trade-off means improving one property by accepting a cost in another. An array provides fast indexing but expensive middle insertion. A hash table provides expected constant-time equality lookup but loses sorted order. An AVL tree spends time on rotations and metadata to obtain a logarithmic height. Choosing a structure means matching these trade-offs to the operations required by the application.

### 10.9 How would you respond if you do not remember an exact formula?

**Answer:**

> I would state the principle first and make the assumption explicit. For example: “I do not remember the exact constant, but the search follows a path whose length is the tree height, so the complexity is $O(h)$; if the tree is balanced, $h=O(\log n)$, and if it degenerates into a chain, $h=O(n)$.” This is better than giving an unjustified exact formula.

### 10.10 Give a one-minute summary of the whole course.

**Answer:**

> Data structures organize information so that different operations can be performed efficiently. Linear structures include arrays, linked lists, stacks, and queues. Trees represent hierarchy and support ordered or prioritized operations through BSTs, balanced trees, heaps, and multiway trees. Graphs model general relationships and lead to traversal, spanning-tree, shortest-path, and flow algorithms. At the algorithmic level, recursion, divide and conquer, dynamic programming, greedy choice, backtracking, and branch and bound provide different ways to reduce a problem. For every method, I would check its invariant, assumptions, time complexity, space complexity, and practical trade-offs.
